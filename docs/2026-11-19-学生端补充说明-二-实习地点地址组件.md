# 学生端补充说明（二）——实习地点地址组件

> 日期：2026-11-19（初版）；2026-11-20（补充实测核验结果）  
> 对象：后端开发  
> 说明：前一份《2026-11-19-学生端接口与功能补充说明》已提交。本文只记录其后的新增变更，避免重复；上一份中的未完成项见文末“承接事项”。

---

## 一、本次变更

学生端“实习经历”的**实习地点**已从普通文本输入改为：

```text
省 / 直辖市 → 市 → 区 / 县 → 街道 / 乡镇 → 详细地址（门牌号/楼栋）
```

前端使用完整的中国行政区划数据（34 个省级行政区，大陆城市/区/街道完整），最终把地址拼成一个中文字符串，继续放在原来的 `location` 字段里提交。

**接口字段没有变化**，仍然是：

```json
{
  "company": "杭州海康威视数字技术股份有限公司",
  "location": "四川省成都市武侯区桂溪街道518号",
  "position": "后端开发实习生",
  "startDate": "2026-07-01",
  "endDate": "2026-08-31"
}
```

- `location`：完整中文地址，单个 String 字段
- `position`：中文岗位名称，单个 String 字段
- 不需要新增省/市/区/街道字段，也不需要改表结构

## 二、需要后端配合

### 1. 允许 `location` / `position` 提交中文（2026-11-20 已修复）

2026-11-19 实测：

```json
{ "code": 10003, "message": "实习地点不能为空", "data": null }
```

前端已确认提交的是中文完整地址，当时后端仍返回 `10003 实习地点不能为空`。

**2026-11-20 复核：已修复。** 实习记录 127 的 `detail.location` 为完整中文地址“四川省成都市都江堰市青城山镇成都东软学院d5 1035”，`detail.position` 为“后端开发”，记录状态为“待审批”，中文提交、落库、详情返回均正常。

后续仍建议后端确认：

- `location` / `position` 是否存在字符集、长度或正则限制；
- 如果确实不支持中文，请明确规则并更新文档 7.5.1 / 7.7.1 / 7.8.1 / 7.9.1；
- 错误提示不要使用“不能为空”，应说明真实原因（如“仅支持英文/数字”）。

### 2. 字段长度

完整地址可能达到 30–60 个中文字符，例如：

```text
香港特别行政区中西区中环皇后大道中XXX号
```

请确认 `location` 字段长度足够（建议不低于 255），并在 7.5.1 中注明最大长度。

### 3. 不需要前端再拆分

目前前端只提交一个完整地址字符串，不提交省/市/区/街道四个独立字段。如果后端希望改成结构化字段，请单独提出，属于新的接口变更，不在本次范围内。

### 4. AI 地址识别依赖 AI 助手的服务范围（2026-11-20 新增）

前端“粘贴地址 → AI 识别”的实现是：

1. `POST /ai/conversations` 创建临时会话；
2. `POST /ai/conversations/{id}/messages` 发送“把地址拆成省/市/区县/街道/详细地址”的提示；
3. 解析返回 JSON；
4. `DELETE /ai/conversations/{id}` 删除临时会话。

**2026-11-20 实测发现**：后端 AI 助手（模型 `glm-5.3-flash`）带有服务范围限制。使用旧提示词“你是一个中国地址解析器”时，助手直接拒绝：

> 地址解析不在我的服务范围内哦……

把提示词改为“学生成长档案申报表单的地点字段拆分，属于档案申报材料”后，同一后端正常返回：

```json
{
  "province": "四川省",
  "city": "成都市",
  "district": "都江堰市",
  "street": "青城山镇",
  "detail": "东软大道"
}
```

前端已按此调整提示词（首次与重试都保留“档案申报”上下文）。

**请后端确认/配合**：

- 保持“档案申报地点字段拆分”这一用法在 AI 助手允许范围内；如后续调整系统提示词，请勿把地址字段拆分判为超范围；
- 或提供一个专用的地址解析接口/助手模式，避免依赖对话提示词的措辞；
- 该用法会频繁创建/删除临时会话，请确认没有严格的频率或会话数量限制。

## 四、前端已完成的改动

1. 实习地点接入省/市/区/街道级联组件；
2. 提交前把地址拼成中文完整字符串写入 `location`；
3. 移除了 `location` / `position` 的“非 ASCII 置空”逻辑，中文原样提交；
4. 编辑旧记录时支持回填：能解析的地址回填到四级选择，解析不了的旧地址保留在详细地址输入框中；
5. 监听外部 `modelValue` 变化后重新回填，切换记录/提交后重置不再残留上一次地址；
6. 省直辖县级市拼接去重：市名=区名只拼一次、跳过“市辖区”、裁掉街道前的市名前缀（儋州/东莞/嘉峪关/济源）；
7. AI 未匹配到的区/街道回退到详细地址，避免“高新区”这类文本被静默丢弃；识别期间若用户手动修改，则丢弃 AI 结果；送 AI 前剥离手机号、身份证号、邮箱；
8. AI 提示词改为“学生档案申报表单的地点字段拆分”，规避 AI 助手服务范围限制（见 二.4）。
