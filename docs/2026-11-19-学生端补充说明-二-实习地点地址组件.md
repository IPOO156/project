# 学生端补充说明（二）——实习地点地址组件

> 日期：2026-11-19  
> 对象：后端开发  
> 说明：前一份《2026-11-19-学生端接口与功能补充说明》已提交。本文只记录其后的新增变更，避免重复；上一份中的未完成项见文末“承接事项”。

---

## 一、本次变更

学生端“实习经历”的**实习地点**已从普通文本输入改为：

```text
省 / 直辖市 → 市 → 区 / 县 → 街道 / 乡镇 → 详细地址（门牌号/楼栋）
```

前端使用完整的中国行政区划数据（34 个省级行政区，大陆城市/区/街道完整），最终把地址拼成一个中文字符串，继续放在原来的 `location` 字段里提交。

**接口字段没有变化**，仍然是：

```json
{
  "company": "杭州海康威视数字技术股份有限公司",
  "location": "四川省成都市武侯区桂溪街道518号",
  "position": "后端开发实习生",
  "startDate": "2026-07-01",
  "endDate": "2026-08-31"
}
```

- `location`：完整中文地址，单个 String 字段
- `position`：中文岗位名称，单个 String 字段
- 不需要新增省/市/区/街道字段，也不需要改表结构

---

## 二、需要后端配合

### 1. 允许 `location` / `position` 提交中文

当前实测：

```json
{ "code": 10003, "message": "实习地点不能为空", "data": null }
```

前端已确认提交的是中文完整地址，但后端仍返回 `10003 实习地点不能为空`。请后端检查：

- `location` / `position` 的校验逻辑是否把非 ASCII 当成空值或非法值；
- 是否存在字符集、长度或正则限制；
- 如果确实不支持中文，请明确规则并更新文档 7.5.1 / 7.7.1 / 7.8.1 / 7.9.1；
- 错误提示不要使用“不能为空”，应说明真实原因（如“仅支持英文/数字”）。

### 2. 字段长度

完整地址可能达到 30–60 个中文字符，例如：

```text
香港特别行政区中西区中环皇后大道中XXX号
```

请确认 `location` 字段长度足够（建议不低于 255），并在 7.5.1 中注明最大长度。

### 3. 不需要前端再拆分

目前前端只提交一个完整地址字符串，不提交省/市/区/街道四个独立字段。如果后端希望改成结构化字段，请单独提出，属于新的接口变更，不在本次范围内。

## 三、测试用例

| 场景       | `location` 示例                          | 期望                             |
| :--------- | :--------------------------------------- | :------------------------------- |
| 普通省份   | `四川省成都市武侯区桂溪街道518号`        | 提交成功，详情可原样返回         |
| 直辖市     | `北京市海淀区中关村街道XX号`             | 提交成功，不能出现“北京市北京市” |
| 特别行政区 | `香港特别行政区中西区中环皇后大道中XX号` | 提交成功，中文正常保存           |
| 中文岗位   | `position: 后端开发实习生`               | 提交成功，不能返回 10003         |
| 超长地址   | 60 个中文字符左右                        | 按字段长度限制处理，不能静默截断 |

## 四、前端已完成的改动

1. 实习地点接入省/市/区/街道级联组件；
2. 提交前把地址拼成中文完整字符串写入 `location`；
3. 移除了 `location` / `position` 的“非 ASCII 置空”逻辑，中文原样提交；
4. 编辑旧记录时支持回填：能解析的地址回填到四级选择，解析不了的旧地址保留在详细地址输入框中。
