# 需求二：E2E 测试套件修复

**背景**：按既定命令清单跑自动化测试，第 8 步报
`Error: page.goto: Protocol error (Page.navigate): Cannot navigate to invalid URL`（`navigating to "/teacher"`）。
曾有一版诊断认为是「`teacher.spec.ts:179` 写了相对路径」——**该诊断不成立**：配置里本就有 `baseURL`，且 `/teacher` 有 `redirect: '/teacher/dashboard'`，相对路径写法正确。真实原因是配置从未被加载 + 用例照一个不存在的界面编写。

**设计取舍（两处，均为应对不稳定环境）**

1. **冒烟用例整个 describe 只登录一次**（`beforeAll` 建页共用），而非每个用例重登——减少请求量以降低触发隧道限流的概率。代价是放弃用例间状态隔离，对「页面能否打开」这类断言可接受，已在代码注释中说明。
2. **`/teacher/archive-view` 只断言「能打开、无 JS 报错」，不断言数据**——该页调的是管理端端点，教师身份被 403，页面稳定显示「覆盖学生 0 人」。这是已知缺陷（报告 §七-4②），待改接 `GET /teacher/students` 后再补数据断言。注释已写明原因。

## 三、运行时验证

| 运行                         | 结果                              |
| ---------------------------- | --------------------------------- |
| 第 1 次全量                  | 13 通过 / 2 flaky / 0 失败        |
| 第 2 次全量                  | 14 通过 / 1 flaky / 0 失败        |
| `npx playwright test --list` | 15 个用例、2 个文件，配置正常加载 |

**遗留：隧道抖动导致的 flaky（环境问题，非用例缺陷）**

失败用例每次不同，均为「登录后 URL 未离开 `/login`」。实测定位过程：

| 通路                         | 三次测得的失败率                                                 |
| ---------------------------- | ---------------------------------------------------------------- |
| 经 Vite 代理                 | 失败 5/15、失败 1/15                                             |
| 直连 natapp 隧道             | 失败 0/15、失败 1/15（`429 Too much connections in one mintue`） |
| 另写的极简自建代理（对照组） | 失败 0/15、**失败 15/15**、失败 0/15                             |

对照组说明失败与代理实现无关，**随隧道自身状态在 0%~100% 间剧烈波动**。失败时接口返回**空 body 500**，dev server 日志为 `http proxy error: Parse Error: Missing expected CR after response line`。

**结论**：natapp 免费隧道不稳定，是当前 E2E 抖动及开发者本机偶发登录失败的共同根因。`retries: 1` 只是缓冲，**根本解法是后端跑在本机或换稳定隧道**（属环境/后端范畴，非本次前端改动能解决）。
