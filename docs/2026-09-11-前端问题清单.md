## 一、已完成的三个维度核对（结论）

### ① 接口对接全量交叉核对 —— 已完成 ✅

把前端 252 个 `request.*` 调用与后端 247 条 Spring 路由做了双向 diff：

| 结果 | 数量 |
| --- | --- |
| 完全匹配 | **243** |
| 前端调了、后端无此路径 | 8（其中 **6 条为误报**：4 条是注释文本、1 条是动态分发 `${type}`、1 条是 `${sub.path}` 动态子路径） |
| 路径存在但 HTTP 方法不一致 | 1（`PUT /ai/conversations/{id}`，属实） |
| **真·缺失接口** | **2 条**（`GET /archive/dimensions`、`PUT /ai/conversations/{id}`） |

**结论：接口对接整体是完成的**，2 条缺失已列入后端清单 P1-3。

> 说明：`POST /applications/${type}` 是动态分发，覆盖了后端 `/applications/competition|scholarship|…` 共 10 个路径，因此反向核对里它们会显示为"后端有、前端未调用"——属**假孤儿**。`POST /awards/research-star/${id}/${sub.path}` 同理（`sub.path` ∈ {projects, software, papers}，后端三个都有）。

### ② 菜单 ↔ 路由 ↔ 守卫 ↔ 首页快捷入口 四方一致性 —— 已完成 ✅

用 esbuild 打包**真实注册表**后在 node 中执行判定，非肉眼核对：

| 核对项 | 结论 |
| --- | --- |
| 16 个注册表模块 → 是否有对应路由 | ✅ 全部有 |
| 路由 `meta.permission` ↔ 注册表模块 id | ✅ 已声明处全部一致 |
| 首页快捷入口 moduleId（6 个）→ 是否在注册表 | ✅ 全部有效 |
| 菜单可见 ↔ 守卫放行（穷举 6 组授权输入） | ✅ **零处"菜单可见但守卫拦截"** |

6 组输入下的顶层菜单数：`teacher+空权限=5`、`counselor+空权限=4`、`teacher+counselor=6`、`admin+空权限=16`、`无角色=1` —— 与 `代码修改记录/2026-09-11.md` 记载一致。

**"孤儿路由"核查**：路由文件中有 20 条不被注册表直接引用，逐条确认后 —— 18 条是**聚合页的子页**（`AccountRole.vue` 直接 import 了 `role-selection`/`account-management` 的 4 个页面；`SystemManagement.vue` 同理）或重定向兜底，**属正常**；唯二异常即下面第四条中的 4 个假数据页面。

## 三、提交类按钮可重复提交（中，共 27 处）

`CLAUDE.md` §3.6 要求「点击确定 → 调接口」必须有**确定按钮 Loading + 禁用态**。实测教师端：

- 提交类按钮**缺 `:loading`**：**27 处**（如 `@click="handleSave|handleSubmit|handleResetPassword"` 等）
- 带 `:loading` 的：46 处

**已确认无内部并发守卫**，例：`src/features/teacher/ability-dimension/AbilityDimension.vue:207` 的「保存」按钮无 `:loading`，且 `handleSave()`（同文件 :63）只做**校验**守卫、无「请求进行中」守卫 —— **双击即发两次请求**。
