## 二、根因分析

### 根因 1：GET /activities 字段名为下划线，前端按驼峰读取 → 真实记录全被过滤

实测（2026-08-23 curl 探测）后端 `GET /activities` 返回的列表项字段为**下划线**：
`archive_type`、`archive_type_label`、`submit_time`、`semester_name`、`current_version`、
`submit_count`、`can_edit`、`can_delete`、`can_withdraw`；而 [useFormRecords.ts](src/shared/composables/useFormRecords.ts)
与 [submission.ts](src/shared/api/submission.ts) 读取的是驼峰 `a.archiveType` / `a.submitTime` / `a.semesterName` → **恒为 undefined**
→ 别名过滤后真实记录全被剔除，列表只剩本地草稿行；提交成功后 `loadRecords` 也拉不到记录 → 下方记录"消失"、
多条记录无法累积。（此前只加了别名映射、漏了字段访问器，别名方案因此未真正生效。）

### 根因 2：挂载时自动把草稿回填进表单 + 保存草稿后不清空表单

[useFormDraft.ts](src/shared/composables/useFormDraft.ts) 在 `onMounted` 调用 `restoreDraft` 把 localStorage 草稿回填进表单；
[useApplicationPage.ts](src/shared/composables/useApplicationPage.ts) 的 `handleSaveDraft` 保存后不重置表单
→ 表单始终残留草稿内容，无法进入"空白待填写"状态。

### 根因 3：loadRecords 拉取失败时把列表清空

`loadRecords` 的 `catch` 直接 `records.value = []` → 提交成功瞬间网络抖动会把已显示记录清空。

## 四、新增范围

#### [activities.ts](src/shared/api/activities.ts)

- `ActivityListItem` 类型对齐后端**下划线**字段（`archive_type`/`archive_type_label`/`submit_time`/`semester_name`/

- `loadRecords` 过滤/取值改读下划线字段并保留驼峰兜底：`a.archive_type ?? a.archiveType`、
  `a.submit_time ?? a.submitTime`、`a.semester_name ?? a.semesterName`；

- 映射结果 `...a` 展开原始字段（供编辑回填），显式字段覆盖。
- `catch` 改为**保持已有列表**（不再清空），避免提交成功瞬间网络抖动导致记录"消失"。

#### [submission.ts](src/shared/api/submission.ts)

- `mapActivityToSubmission` 同步改读下划线字段（`archive_type`/`archive_type_label`/`submit_time`/`semester_name`）。

#### [useFormDraft.ts](src/shared/composables/useFormDraft.ts)

- 新增 `autoRestore` 选项（默认 `true`）：`false` 时挂载不再自动回填草稿到表单。
- `saveLocal` 增加空表单守卫：`isNonEmpty(form)` 为 false 时不写 localStorage
  （保存草稿后清空表单会触发深 watcher，防止其抹掉已存草稿）。

#### [useApplicationPage.ts](src/shared/composables/useApplicationPage.ts)

- `useFormDraft(effectiveDraftKey, form, { autoRestore: false })`：申报表单默认空白，草稿只通过下拉记录"编辑"回填。
- `handleSaveDraft`：保存草稿后 `resetForm()` + `cancelEdit()` → 表单转空白待填写态；
  修改草稿需在下拉记录点"编辑"再回填。

# 2026-08-23 修改记录（需求 2：打开应用直接进入内部、不显示登录页）

> 需求：**打开应用时未登录却直接进入学生端内部，正常应显示登录界面**——
> 路由守卫只检查 `localStorage` 里是否存在 token、不验证其时效；历史版本无条件把 token 写入
> `localStorage`，跨浏览器会话永久残留 → 残留 token 使守卫放行、绕过登录页。

## 一、根因分析

| 根因               | 说明                                                                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| token 无条件持久化 | [user.ts](src/app/stores/user.ts) 旧 `setToken` 直接把 token 写进 `localStorage`，不区分「记住我」；`localStorage` 跨浏览器重启保留，导致旧会话 token 永久生效             |
| 路由守卫只看存在性 | [routes.ts](src/app/router/routes.ts) 守卫 `const token = localStorage.getItem('token')` 仅判断 token 是否存在，不验证有效性/时效 → 残留 token 存在即放行进入 `/dashboard` |
| 无启动清理         | 应用启动时未清理无「记住我」标记的孤立 localStorage 令牌                                                                                                                   |

## 二、删除范围（先记录）

| 文件                                     | 删除内容                                                                                                                                                                                                                                                    |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [user.ts](src/app/stores/user.ts)        | 旧 `setToken` 中 `localStorage.setItem('token', val)` 无条件写 localStorage 的实现；`token` ref 的 `localStorage.getItem('token')` 初始化；`logout` 中直接 `localStorage.removeItem('token'/'refresh_token')`                                               |
| [request.ts](src/shared/api/request.ts)  | 请求拦截器 `localStorage.getItem('token')` 直读；`tryRefreshToken` 中 `localStorage.getItem('refresh_token')` 直读、刷新成功后的 `localStorage.setItem` 直写、失败 `catch` 中两条 `localStorage.removeItem`；`forceLogout` 中两条 `localStorage.removeItem` |

| [Login.vue](src/features/auth/Login.vue) | `localStorage.setItem('refresh_token', ...)` 直写                                                                                                                                                                                                           |
| [teacher.ts](src/shared/api/teacher.ts)  | 三处文件下载/模板下载的 `localStorage.getItem('token')` 直读（415/449/716 行附近）                                                                                                                                                                          |

## 三、新增范围

#### [token.ts](src/shared/utils/token.ts)（新文件）

- 统一令牌存储工具，按「记住我」区分存储域：
  - 默认（未勾选记住我）→ 仅 `sessionStorage`：关闭浏览器/标签页即失效，重开应用显示登录页；
  - 勾选记住我 → `localStorage`：跨会话保持登录；
  - 读取优先 `sessionStorage`（当前会话最新），其次 `localStorage`。
- 导出：`getToken` / `getRefreshToken` / `setToken(token, remember)` / `setRefreshToken(token, remember)` /
  `writeTokenPreservingSource`（刷新回写沿用旧存储，避免「记住我」被降级为会话级）/ `clearAuth` / `initAuthState`。
- `initAuthState()`：启动时清理历史遗留的孤立令牌——localStorage 中的 token 若无「记住我」标记
  （REMEMBER_KEY=`remember_me`），即旧版本无条件写入的残留，直接清除，避免未登录直接进入系统。

#### [main.ts](src/main.ts)

- `import { initAuthState }`；在 `createApp` 前调用 `initAuthState()`（须在 `app.use(router)` 之前执行，
  确保首个导航守卫读到的是清理后的令牌状态）。

#### [routes.ts](src/app/router/routes.ts)

- 守卫改为 `const token = getToken()`（统一走工具读取 session/local 双存储）。

#### [user.ts](src/app/stores/user.ts)

- `token` ref 改为 `ref(getToken())`；`setToken(val, remember = false)` 改走 `persistToken` 工具；
  `logout` 改用 `clearAuth()`。

#### [request.ts](src/shared/api/request.ts)

- 请求拦截器与刷新逻辑全部改走工具函数；刷新成功回写用 `writeTokenPreservingSource(accessToken, refreshToken)`；
  失败与强制登出统一 `clearAuth()`。

#### [Login.vue](src/features/auth/Login.vue)

- 登录成功写入：`userStore.setToken(res.accessToken, loginForm.remember)` + `setRefreshToken(res.refreshToken ?? '', loginForm.remember)`。

#### [teacher.ts](src/shared/api/teacher.ts)

- 三处下载 Authorization 改 `Bearer ${getToken()}`（管理员端共用同一登录态，避免学生端改动后管理员请求不带 token）。
