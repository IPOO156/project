# 2026-08-23 修改记录

> 需求：**申报信息（档案申报 + 奖项报名）草稿/记录列表逻辑梳理**——

## 二、根因分析

### 根因 1：GET /activities 字段名为下划线，前端按驼峰读取 → 真实记录全被过滤

实测（2026-08-23 curl 探测）后端 `GET /activities` 返回的列表项字段为**下划线**：
`archive_type`、`archive_type_label`、`submit_time`、`semester_name`、`current_version`、
`submit_count`、`can_edit`、`can_delete`、`can_withdraw`；而 [useFormRecords.ts](src/shared/composables/useFormRecords.ts)
与 [submission.ts](src/shared/api/submission.ts) 读取的是驼峰 `a.archiveType` / `a.submitTime` / `a.semesterName` → **恒为 undefined**
→ 别名过滤后真实记录全被剔除，列表只剩本地草稿行；提交成功后 `loadRecords` 也拉不到记录 → 下方记录"消失"、
多条记录无法累积。（此前只加了别名映射、漏了字段访问器，别名方案因此未真正生效。）

### 根因 2：挂载时自动把草稿回填进表单 + 保存草稿后不清空表单

[useFormDraft.ts](src/shared/composables/useFormDraft.ts) 在 `onMounted` 调用 `restoreDraft` 把 localStorage 草稿回填进表单；
[useApplicationPage.ts](src/shared/composables/useApplicationPage.ts) 的 `handleSaveDraft` 保存后不重置表单
→ 表单始终残留草稿内容，无法进入"空白待填写"状态。

### 根因 3：loadRecords 拉取失败时把列表清空

`loadRecords` 的 `catch` 直接 `records.value = []` → 提交成功瞬间网络抖动会把已显示记录清空。

## 四、新增范围

#### [activities.ts](src/shared/api/activities.ts)

- `ActivityListItem` 类型对齐后端**下划线**字段（`archive_type`/`archive_type_label`/`submit_time`/`semester_name`/
  `current_version`/`submit_count`/`can_edit`/`can_delete`/`can_withdraw`），驼峰字段降级为兼容别名并注明"读取优先下划线"。

#### [useFormRecords.ts](src/shared/composables/useFormRecords.ts)

- `loadRecords` 过滤/取值改读下划线字段并保留驼峰兜底：`a.archive_type ?? a.archiveType`、
  `a.submit_time ?? a.submitTime`、`a.semester_name ?? a.semesterName`；
  `typeLabel` 优先用后端 `archive_type_label`。
- 映射结果 `...a` 展开原始字段（供编辑回填），显式字段覆盖。
- `catch` 改为**保持已有列表**（不再清空），避免提交成功瞬间网络抖动导致记录"消失"。

#### [submission.ts](src/shared/api/submission.ts)

- `mapActivityToSubmission` 同步改读下划线字段（`archive_type`/`archive_type_label`/`submit_time`/`semester_name`）。

#### [useFormDraft.ts](src/shared/composables/useFormDraft.ts)

- 新增 `autoRestore` 选项（默认 `true`）：`false` 时挂载不再自动回填草稿到表单。
- `saveLocal` 增加空表单守卫：`isNonEmpty(form)` 为 false 时不写 localStorage
  （保存草稿后清空表单会触发深 watcher，防止其抹掉已存草稿）。

#### [useApplicationPage.ts](src/shared/composables/useApplicationPage.ts)

- `useFormDraft(effectiveDraftKey, form, { autoRestore: false })`：申报表单默认空白，草稿只通过下拉记录"编辑"回填。
- `handleSaveDraft`：保存草稿后 `resetForm()` + `cancelEdit()` → 表单转空白待填写态；
  修改草稿需在下拉记录点"编辑"再回填。

## 五、行为说明

- **档案申报 + 奖项报名（竞赛之星/双创之星/科研项目/软著/论文）共用 `useApplicationPage`**，上述修复自动生效。
- **草稿数量**：每类型本地草稿仍为 **1 条**（localStorage 单槽 `form_draft_<key>`；后端无草稿增删改接口）。
  已提交记录可多条累积（后端 `GET /activities` 全部返回并展示）。
- **真实记录编辑回填受限**：后端 `GET /activities/{id}`（6.2）返回 30001 未实现，编辑已提交记录只能回填列表摘要字段；
  本地草稿编辑可完整回填（草稿行携带全部表单字段）。
- 同日另完成：`vite.config.js/.ts` 代理 target 更新为新隧道 `http://u875afaf.natappfree.cc`（重启 dev server 生效）。
