# 致后端：权限数据未下发导致菜单塌空（含 1 处越权缺口）

- **日期**：2026-09-11
- **提出方**：前端
- **紧急度**：P0 —— 其中「教师端日志接口无权限校验」**不应带上线**
- **背景**：前端菜单与路由授权已由「前端硬编码角色枚举」切换为「`GET /auth/me` 的 permissionCode 驱动」，切换后暴露出以下数据/接口问题

---

## 一、现象

| 端 | 改造前菜单 | 现在菜单 |
| --- | --- | --- |
| 管理员端 | 19 项 | **1 项** |
| 教师端 | 5 项 | **1 项** |

仅存的那 1 项是「日志查看」—— 因为它是前端 19 个模块里**唯一挂通配码 `*`** 的（改造期的临时措施），对所有人放行。也就是说：**所有人的 `/auth/me.permissions` 都一个模块权限码都没匹配上。**

## 二、实测证据（抓包，非推测）

教师账号登录后 `GET /api/v1/auth/me`，**HTTP 200**，请求头 `Authorization: Bearer ...` 正常，响应体：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "userId": 2,
    "userNo": "T20230001",
    "name": "李四",
    "roles": ["teacher"],
    "roleNames": ["教师"],
    "permissions": [],
    "scopes": [],
    "avatar": null
  },
  "trace_id": "req-20260911-152300-b92a9a66",
  "timestamp": "2026-09-11T15:23:00+08:00"
}
```

**结论：请求是成功的，是 `permissions` 与 `scopes` 双双为空。** 即线上库的 `role_permissions`、`role_scopes` 整体未按种子初始化。

**自检 SQL**（请在线上库执行）：

```sql
-- 期望：admin 17 条、teacher 14 条、counselor 14 条（以仓库种子为准）；若为 0 即命中本问题
SELECT r.code, COUNT(rp.id) AS grant_count
FROM roles r LEFT JOIN role_permissions rp ON rp.role_id = r.id
WHERE r.code IN ('admin', 'teacher', 'counselor')
GROUP BY r.code;

-- 角色范围授权同理
SELECT r.code, COUNT(rs.id) AS scope_count
FROM roles r LEFT JOIN role_scopes rs ON rs.role_id = r.id
GROUP BY r.code;
```

对照种子：`seed_admins.sql`（admin，permission id 8~23 + 37）、`seed_teachers.sql`（teacher/counselor，permission id 24~34 + 18 + 35 + 36）。

## 三、需要后端处理的（按优先级）

### P0-1 同步线上库的 `role_permissions` 与 `role_scopes`

按种子把授权数据补齐。注意管理员侧同样为空 —— 与 `AdminAuthService.java:118-131` 的设计一致（持 `admin` 角色直接 `return` 放行、不校验任何权限码），所以线上库很可能**从未给 admin 角色授予过权限码**。

### P0-2 教师端日志接口校验的 `log:view` 未授予教师角色

> **勘误**：本节此前写作「`GET /teacher/logs` 无权限校验，任何登录用户都能看日志」，**该结论有误**。实际是接口有校验、缺的是角色授权，方向相反。

`GET /teacher/logs` → `TeacherLogService.listLogs()` 首行即校验（`service/Lzw/TeacherLogService.java:76`）：

```java
adminAuthService.requireAdminOrPermission(teacherId, "log:view");
```

`requireAdminOrPermission` 在非 admin 且 `permissions` 为空时直接抛 20005，**不存在越权**。

问题在授权数据：`log:view` 只在 `seed_admins.sql:73`（permission id 22）中定义并授予 admin，`seed_teachers.sql` 中**没有**它。因此教师访问教师端日志必然 **20005 无访问权限**（线上库 teacher 无任何 `role_permissions`，更是必然）。

**后果**：前端为让「日志查看」菜单可见而挂的通配码 `*`，只做出了「菜单可见」，**点进去取不到数据** —— 教师端目前唯一可见的菜单项实际不可用。

**期望**：为 teacher / counselor 授予 `log:view`（或新建教师端日志独立码并授予），前端随后移除通配码。

### P0-3 `TeacherDelegationController` 有声明无校验

`src/main/java/com/example/studentarchives/controller/Fmy/TeacherDelegationController.java` 的 Javadoc 标注「权限码：`delegate:manage`」，但**方法体内未调用任何鉴权**；且 `/teacher/**` 在 `config/SecurityConfig.java:72-78` 中仅要求 `authenticated`。

**后果：任何登录用户都能创建/取消自己的审批委托。** 请补权限码校验。

### P1-1 五个权限码「代码在校验、`permissions` 表里没建」

以下码在 Service 层被实际校验，但种子 `permissions` 表中**不存在**，因此永远不会出现在任何人的 `permissions` 里：

| 权限码 | 校验位置 |
| --- | --- |
| `archive:view` | `service/Fmy/AdminArchiveService.java:101` |
| `statistics:view` | `service/Fmy/AdminStatisticsService.java:80` |
| `archive:export` | `service/Fmy/AdminExportService.java:145` |
| `form:template:manage` | `service/Fmy/AdminFormTemplateService.java:65` |
| `semester:import` | `service/Lzw/SemesterManageService.java:75` |

已核对：这 5 个码在 `seed_admins.sql`、`seed_teachers.sql`、`seed_roles_permissions.sql` 中**均无记录**。请建码 + 授予 admin（教师/辅导员是否也需要请一并明确）。

### P1-2 账号管理权限码不一致，需裁定

- **代码校验**：`user:view` / `user:manage`（`service/Lzw/UserManageService.java:111` 等）
- **种子建的是**：`system:user:manage`（`seed_admins.sql:55`，permission id=11）

两者对不上：种子永远无法让 `user:manage` 生效，代码永远收不到 `system:user:manage`。**请裁定统一为哪一个**，前端据此调整。

### P1-3 审批委托：授权方向与业务口径相反 + Service 语义不匹配

**业务口径（产品已确认）**：审批委托只能「管理员 → 教师」，教师之间不可互相委托，**教师端不应出现该模块**。

后端现状：

1. **种子方向反了** —— `delegate:manage`（permission id=36）在 `seed_teachers.sql:99,113` 中授予了 teacher(3)、counselor(4)，而 `seed_admins.sql:82-99` 中 admin 的授权**不含 36**；
2. **Service 语义无法表达「管理员委托教师」** —— `service/Fmy/TeacherDelegationService.java:166-227` 的 `delegatorId` 直接取自当前登录人，并校验「委托人须持有该 roleId + 范围覆盖」，实现的是**自己委托自己**；管理员不持有 role 3 时传 `roleId=3` 会被拒；
3. **附带缺陷** —— 该页「被委托人」下拉调用管理端 `GET /admin/users`，教师调用**必然 403**。

**请明确**：`delegate:manage` 是否改为授予 admin（或新建管理员专属码）；「管理员委托教师」的接口语义（`delegatorId` 是否固定为当前登录人、`roleId` 是否必传、`isAuditor` 当前含 admin 与「受托人必须是教师」的报错文案不符是否收窄）。若最终仍需教师看到「委托给我的」记录，请提供独立权限码（如 `delegate:view`）与教师端可访问的被委托人数据源，避免复用管理端接口。

## 四、前端当前的过渡措施（后端不用处理）

- 前端已加**空数据兜底**：`permissions` 为空时按角色基线展示菜单（教师 5 项 / 辅导员 4 项，与改造前一致），并给用户一条非阻断提示。
- **该兜底只在 `permissions` 为空时生效**，后端把授权数据下发到位后**自动失效**，无需前端回滚。
- 但**「日志查看」的通配码 `*` 必须在上线前移除**，前置条件是 P0-2 为教师角色授予 `log:view`。
