# 免验证码登录机制 — 后端配置说明

**背景**：前端自动化测试（Playwright e2e）需要登录 20+ 次/天，每次手动输入 4 位图形验证码效率低下。后端已实现"测试环境白名单账号 + 请求头密钥"跳过验证码校验的完整机制，本次只需在 dev.yml 补配置即可生效。

---

## 一、机制概览（后端已实现，无需改代码）

| 环节 | 位置 | 状态 |
|------|------|:----:|
| 策略判定 | `CaptchaSkipPolicy.java`（4 道关卡 fail-closed） | ✅ 已实现 |
| 登录调用 | `AuthController.login()` 把 header + userNo 传给策略 | ✅ 已实现 |
| Service 分支 | `AuthService.login(..., skipCaptcha)` 跳过验证码校验 | ✅ 已实现 |
| 审计日志 | 每次免验登录 `log.warn("[CAPTCHA-SKIP-AUDIT] ...")` | ✅ 已实现 |
| 配置类 | `AuthCaptchaProperties.java`（prefix: `auth.captcha`） | ✅ 已实现 |
| test profile | `application-test.yml`（完整配置，CI 用） | ✅ 已就绪 |
| **dev profile** | `application-dev.yml`（**缺 captcha 配置**） | ❌ **需要补** |
| prod profile | `application-prod.yml`（已关闭 + 硬编码守卫） | ✅ 已兜底 |

### 4 道 fail-closed 关卡（全部通过才跳过）

```java
// CaptchaSkipPolicy.shouldSkip() —— 任一不满足即 return false
1. active profiles 不含 prod/production/prd（硬编码守卫，不可配置）
2. auth.captcha.skip-code-verify = true（总开关）
3. 所有 active profiles 落在 skip-allowed-profiles 内
4. skip-secret 已配置（非空）且与请求头值常量时间相等
5. 登录账号在 skip-users 白名单内
```

## 二、根因：为什么前端发了 header 还是 400

前端发的请求：
```
POST /api/v1/auth/login
Header: X-Captcha-Skip-Token: true
Body: { userNo: "202401002", password: "...", captchaCode: "", captchaKey: "" }
```

后端返回：`{ code: 10001, message: "验证码不能为空" }`

**原因链路**：
```
后端启动 profile = dev（application.yml active: dev）
Spring Boot 加载 application.yml → application-dev.yml
application-test.yml 完全没加载 ← 配置只在 test.yml 里

AuthCaptchaProperties 所有字段走默认值：
  skipCodeVerify = false        ← 默认关闭
  skipAllowedProfiles = []       ← 空
  skipUsers = []                ← 空
  skipSecret = ""                ← 空

CaptchaSkipPolicy.shouldSkip("202401002", "true") 执行：
  关卡 1（prod 守卫）→ 通过（dev 不是 prod）
  关卡 2（总开关）   → skipCodeVerify=false → return false ← 在此失败！

skipCaptcha = false → 走正常验证码校验 → captchaCode 为空 → 10001
```

## 三、需要后端做的事（仅此一件）

**在 `application-dev.yml` 末尾追加以下配置**：

```yaml
# ===== 免验证码登录（测试环境自动化登录用）=====
# 机制见 CaptchaSkipPolicy.java，4 道 fail-closed 关卡
# 生产环境不会生效（prod.yml skip-code-verify: false + 硬编码 prod 守卫）
auth:
  captcha:
    # 总开关
    skip-code-verify: true

    # profile 白名单：dev 是当前开发 profile
    skip-allowed-profiles:
      - dev

    # 仅这些账号可以免验证码登录；其余账号照常校验
    skip-users:
      - 202401002   # 学生测试号
      - A00002      # 管理员测试号
      - T00003      # 教师测试号

    # 前端发送的请求头名称
    skip-header-name: X-Captcha-Skip-Token

    # 密钥：从环境变量读取，本地默认 dev-local-secret
    # 生产环境 CAPTCHA_SKIP_SECRET 未设置时默认空字符串 → 关卡 4 自动失败
    skip-secret: ${CAPTCHA_SKIP_SECRET:dev-local-secret}
```

### 为什么 secret 用默认值 `dev-local-secret`

| 场景 | secret 值 | 效果 |
|------|----------|------|
| 开发者本地（没设 `.env`） | `dev-local-secret`（默认值） | ✅ 可用，前端也发同样值 |
| CI / e2e（环境变量覆盖） | CI 里的真实密钥 | ✅ 可用，前端按环境变量发 |
| 生产（profile=prod） | **不生效**（硬编码守卫拦截） | ✅ 安全 |

## 四、生产安全（两层兜底，零维护成本）

### 第一层：prod.yml 已关闭

```yaml
# application-prod.yml
auth:
  captcha:
    skip-code-verify: false        # 总开关关
    skip-allowed-profiles: []       # 空
    skip-users: []                  # 空
    skip-secret: ""                 # 空
```

### 第二层：硬编码生产守卫（不可配置绕过）

```java
// CaptchaSkipPolicy.java —— L45 + L110-114
private static final Set<String> PRODUCTION_PROFILES = Set.of("prod", "production", "prd");

for (String profile : activeProfiles) {
    if (PRODUCTION_PROFILES.contains(profile.toLowerCase())) {
        return "命中生产 profile，免验证码能力被强制禁用";  // 直接 return false
    }
}
```

**就算有人手滑把 prod.yml 的 `skip-code-verify` 改成了 `true`，这层硬编码也会拦住。**

### 生产部署时需要后端做什么？

**什么都不用做。** prod.yml 配置不变，硬编码守卫不变，正常打包部署即可。

## 五、验证 checklist

dev.yml 追加配置 + 重启后端后，按以下顺序验证：

### 1. 启动日志确认（后端控制台）

```
[CAPTCHA-SKIP] 免验证码登录已就绪: activeProfiles=[dev], skipUsers=[202401002, A00002, T00003]
```

看到这条 WARN 说明配置正确加载、开关已打开。**如果没看到**，说明：
- dev.yml 没追加成功，或
- Spring Boot 缓存了旧配置（`mvn clean` 后再启动）

### 2. 免验证码登录成功（白名单账号）

```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -H "X-Captcha-Skip-Token: dev-local-secret" \
  -d '{"userNo":"202401002","password":"123456","captchaCode":"","captchaKey":""}'
```

期望：返回 200 + JWT token，**不返回 10001**。

后端控制台应看到：
```
[CAPTCHA-SKIP-AUDIT] 免验证码登录: userNo=202401002, ip=..., userAgent=...
```

### 3. 正式账号仍然被拦截（安全验证）

```bash
# 假设 202401001 不在白名单
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -H "X-Captcha-Skip-Token: dev-local-secret" \
  -d '{"userNo":"202401001","password":"123456","captchaCode":"","captchaKey":""}'
```

期望：返回 `10001 验证码不能为空`（关卡 5 白名单不通过 → 走正常校验 → 验证码为空报错）。

### 4. 密钥错了也被拦截

```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -H "X-Captcha-Skip-Token: wrong-secret" \
  -d '{"userNo":"202401002","password":"123456","captchaCode":"","captchaKey":""}'
```

期望：返回 `10001 验证码不能为空`（关卡 4 密钥不匹配）。
