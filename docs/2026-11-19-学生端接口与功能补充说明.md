## 二、问题详情与期望

### 1. 学期基础数据只有一条

**现象**

`GET /common/semesters` 在 2026-11-19 只返回 `2025-2026-第1学期`；**2026-11-20 复核**已返回 6 个标准学期（2024-2025、2025-2026、2026-2027 的第 1/2 学期），但仍**没有小学期/暑期学期**。

**影响**

- 学生/测试无法选择其他学期；
- 获奖时间与学期无法自然对应；
- 前端会按所选学期的标准月份范围禁用越界月份（学期数据补齐后即可正常选择其他学期）。

**期望**

后端补齐 `semesters` 表中启用中的学期（按现有文档 2.2，`status=1` 且未删除），包括第一学期、第二学期、**小学期/暑期学期**，并确认返回顺序（文档为 `start_date` 倒序）。

**文档补充**

- 2.2 建议补充响应中的 `startDate` / `endDate` 字段说明（前端已在使用这两个字段做日期联动）。

### 2. 证书编号 `certificateNo`（需要后端支持）

**现象**

- 现有文档 7.1 的**请求参数表没有** `certificateNo`；
- 但 7.1 的**请求示例**里有 `"certificateNo": "CERT-2025-001"`；
- 实际后端详情接口**不返回** `certificateNo`；
- 前端之前按示例做了“证书编号”输入框，用户填写后既看不到、也无法用于查重。

**后端返回的真实记录（节选）**

```json
{
  "id": 114,
  "type": "archive",
  "title": "2026年度全国大学生计算机应用能力与数字素养大赛，暨第九届传智杯全国大学生数智创新与A应用大赛",
  "archive_type": "academic_competition",
  "semester_name": "2025-2026-第1学期",
  "detail": {
    "obtainedTime": "2026-10-01",
    "competitionName": "2026年度全国大学生计算机应用能力与数字素养大赛，暨第九届传智杯全国大学生数智创新与A应用大赛",
    "competitionType": "academic",
    "competitionTypeLabel": "学科类",
    "awardLevel": "first",
    "awardLevelLabel": "一等奖",
    "participantRole": "leader",
    "participantRoleLabel": "负责人"
  }
}
```

可以看到 `detail` 中没有 `certificateNo`。

**请后端按以下方式支持**

- `POST/PUT /applications/competition` 接收并落库 `certificateNo`；
- `GET /activities/archive/{id}` 的 `detail` 返回该字段；
- 7.1 参数表补上 `certificateNo`（以及示例中的 `issuingUnit`、`validUntil`）。

这样证书编号才能用于查重，也能在详情里展示。

**前端当前处理**

学科竞赛页已恢复“证书编号”输入框，提交时随请求体发送 `certificateNo`；后端完成落库与详情返回后，前端即可展示。

### 3. 评选说明没有正文

**现象**

学科竞赛“评选说明”弹窗能显示标题“学科竞赛评选说明”，但正文、申报要求、注意事项为空：

> 暂无评选说明，请联系管理员补充该类型的申报配置。

**现有文档与实际的差异**

- 文档 7.0.2 / 8.1.3 约定返回归一化结构：
  `type / typeLabel / title / content / requirements / notes / updatedAt`
- 实际 `/applications/{type}/guide` 返回的是原始字段（前端注释与实测）：
  `archiveType / typeName / evaluateDesc / evaluateRequirements / evaluateNotes / applyDesc`
- 数据来源为 `archive_type_configs.evaluate_desc / evaluate_requirements / evaluate_notes`（文档 7.0.2 已注明）。

**判断**

- 前端已兼容两种响应形状，因此**不是前端渲染问题**；
- 当前正文为空，说明 `archive_type_configs` 中对应学校 + `academic_competition` 的 `evaluate_desc/evaluate_requirements/evaluate_notes` 没有配置内容。

**期望后端**

1. 补齐 `archive_type_configs` 中各档案类型/奖项类型的评选说明数据；
2. 统一响应形状，二选一：
   - 按现有文档返回归一化字段（后端做转换）；或
   - 保留原始 `evaluate*` 字段，更新文档 7.0.2 / 8.1.3 的响应示例与字段说明。
3. 前端两种都能渲染，但同一后端不应出现档案侧和奖项侧形状不一致。

### 4. 实习地点/岗位中文（已确认后端问题）

**现象**

用户在实习经历中填写中文“北京”“后端开发”，提交后后端返回：

```json
{ "code": 10003, "message": "实习地点不能为空", "data": null }
```

**结论**

前端已移除 `location/position` 的“非 ASCII 置空”逻辑，提交时中文会原样进入请求体，前端侧已确认无问题。

**2026-11-20 复核：已修复。** 实习记录 127 的 `detail.location` 为完整中文地址“四川省成都市都江堰市青城山镇成都东软学院d5 1035”，`detail.position` 为“后端开发”，记录状态为“待审批”，说明中文提交、落库、详情返回均正常，不再返回 `10003`。

**请后端处理**

- `location/position` 是普通文本字段，文档 7.5.1 也没有 ASCII 限制；
- 请检查校验逻辑，确认是否把非 ASCII 当作空值或非法值；
- 若确实不支持中文，请说明规则并更新文档 7.5.1 / 7.7.1 / 7.8.1 / 7.9.1；
- 错误提示不要使用“不能为空”，应明确说明真实原因（如“仅支持英文/数字”）。

> 实习地点已接入“省/市/区/街道”地址组件，地址一定是中文，请后端按普通文本字段支持中文。

### 5. 获奖时间与学期必须匹配

**现象**

后端接受 `obtainedTime=2026-10-01` + `semester=2025-2026-第1学期`，未报错。

**要求**

- 获奖时间**必须**落在所选学期范围内；
- 第一学期：当年 9 月—次年 1 月；第二学期：次年 2 月—7 月；
- **小学期/暑期学期**：按学校实际设置的起止日期校验（通常 6—8 月，以后端 `startDate/endDate` 为准）；
- 超出范围时后端必须拒绝，返回明确的错误码/提示，并更新 7.1 文档；
- 前端已按学期标准月份范围禁用越界月份，并在提交前再次校验；小学期名称无法从名称解析时不硬编码月份，避免误拦，最终以后端校验为准。
