## 一、目标

开发环境跳过图形验证码校验，只对指定测试账号开放，且必须传约定 secret header。
**跳过的是 AuthService.login L137-148 验证码校验这一步，后面的限流 / 密码匹配 / Token 生成 / 日志全部正常执行。**

### 2.3 新建 CaptchaSkipProperties.java — 配置绑定类

**文件**：`D:\StudentArchives\src\main\java\com\example\studentarchives\config\CaptchaSkipProperties.java`

```java
package com.example.studentarchives.config;

import lombok.Data;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.context.annotation.Configuration;

import java.util.ArrayList;
import java.util.List;

/**
 * 验证码跳过配置（仅开发环境生效）
 */
@Data
@Configuration
@ConfigurationProperties(prefix = "auth.captcha")
public class CaptchaSkipProperties {

    /** 是否开启跳过验证码（dev=true, prod=false） */
    private boolean skipEnabled = false;

    /** 白名单：仅这些 userNo 可免验证码登录 */
    private List<String> whitelist = new ArrayList<>();

    /**
     * 免验密钥：调用方必须在请求头传 X-Test-Secret 与此值一致
     * 默认值 dev-only-secret-change-me 仅用于开发，生产应通过环境变量覆盖
     */
    private String skipSecret = "";

    /**
     * 三层防护短路判断：全部通过才返回 true
     * 调用点：AuthService.login() 第一步替换此判断
     */
    public boolean canSkip(String userNo, String headerSecret) {
        if (!skipEnabled) {
            return false;                                          // 层1: profile + 开关
        }
        if (whitelist == null || !whitelist.contains(userNo)) {
            return false;                                          // 层2: 白名单
        }
        return skipSecret != null && skipSecret.equals(headerSecret); // 层3: secret header
    }
}
```

**文件**：`d:\project\src\features\auth\Login.vue`

```typescript
// 前端判断：仅 Vite dev 构建 + 登录表单填了白名单账号时，自动附加 header
const IS_DEV = import.meta.env.DEV

// 在 submitLogin 内：
const testSecret = IS_DEV && loginForm.username.match(/^(A00002|T00003|202401002)$/)
  ? 'dev-only-secret-change-me'
  : undefined

const headers: Record<string, string> = {}
if (testSecret) {
  headers['X-Test-Secret'] = testSecret
  // 跳过前端验证码非空校验（后端免验，前端不需要拦截）
  loginForm.captcha = loginForm.captcha || '0000'
}

await login({
  userNo: loginForm.username,
  password: loginForm.password,
  captchaKey: captchaKey || 'skipped',
  captchaCode: loginForm.captcha,
  rememberMe: loginForm.remember,
```

## 四、三层防护审计

| 层 | 机制 | 兜底 |
|----|------|------|
| 1 | `skip-enabled: false`（prod.yml） | Spring Boot profile 隔离，生产即使有人知道白名单和 secret，开关也是关的 |
| 2 | 白名单 | dev 环境里即使开关开了，非测试账号照样要验证码 |
| 3 | `X-Test-Secret` header | 即使白名单账号，没有 header 照样正常走验证码 |
| 审计 | `log.warn("[免验证码登录] ✅ ...")` | 每次免验都有独立 warn 日志，可 Grep 审计 |
| 生产兜底 | `import.meta.env.DEV` tree-shaking | 生产 bundle 里没有跳过按钮和 secret 逻辑 |

### 风险场景覆盖

| 场景 | 能否绕过 |
|------|:--------:|
| 生产 profile 被误配为 dev + skip-enabled=true | ❌ skip-enabled 在 prod.yml 硬编码 false |
| 攻击者知道 secret header 值 | ❌ 生产 skip-enabled=false；dev 还要白名单账号 |
| 白名单账号在生产被试 | ❌ 生产 skip-enabled=false，正常验证码校验 |
| 有人 commit 了真实 secret 到 git | ❌ secret 用 `${AUTH_CAPTCHA_SKIP_SECRET:default}` 占位，真实值在 .env（gitignore） |
