# 教师端审核详情「当前环节」误显示与重复字段修复

- **日期**：2026-11-12
- **修改人**：ry
- **本次需求**：教师端材料审核出现「审核历史两条通过，列表仍显示待审批」的困惑；同时审核详情「填报内容」出现 `competitionTypeLabel`、`awardLevelLabel` 两行原始字段名。
- **排查结论**：
  - 该申报走的是三级审批流（学科竞赛审批流程：1 辅导员审核 → 2 系主任审核 → 3 院长审核）。第 1、2 级已通过，第 3 级仍是待办，因此待审核列表的「待审批」是当前任务状态，**状态流转本身正确，不是审核通过后未刷新**。
  - 误导来自前端：详情接口只返回已完成节点的 `approvalHistory`，不返回当前节点号；页面却把 `approvalHistory.length` 当作「当前环节」显示为「2 步」，看起来像已经走完。
  - 后端 `detail` 同时返回枚举码与 `*Label`（如 `competitionType` + `competitionTypeLabel`），前端两行都渲染；`*Label` 的 key 不在 `AUDIT_DETAIL_LABELS` 中时就直接把 key 当行标题显示。
- **改动范围**：仅教师端审核详情摘要组件；后端审批流与接口未改动。

| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `src/features/teacher/review/AuditDetailSummary.vue` | 删除「当前环节」= `approvalHistory.length` + `步` 的显示逻辑，改为只陈述已通过与待审事实                   |

# 输入框选中（焦点）动画改为平滑扩散

- **日期**：2026-11-12
- **修改人**：ry
- **本次需求**：输入框获得焦点时，外圈描边是瞬间跳出的，与边框颜色渐变不同步，观感生硬；改为平滑扩散的焦点动画。
- **根因**：教师端 / 管理员端控制层焦点由 `outline: 2px solid` 实现，`outline` 属性不支持过渡（transition 只监听了 `box-shadow`），因此选中时外圈瞬跳；1px 内边线则因 `box-shadow` 有 120ms 过渡，两者不同步。
- **改动范围**：仅 `controls.scss` 中控制层焦点样式（输入框 / 文本域 / 下拉选择器）；学生端样式、业务组件与后端均未改动。

## 一、删除范围

| 文件 / 位置                       | 删除内容                                                                          |
| --------------------------------- | --------------------------------------------------------------------------------- |
| `src/assets/styles/controls.scss` | 删除输入框、文本域、选择器焦点态中的 `outline: 2px solid` + `outline-offset: 2px` |

## 二、新增范围

| 文件 / 位置                       | 新增内容                                                                                                                                           |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/assets/styles/controls.scss` | 输入框 / 选择器用 `::after` 伪元素画 2px 外环（`inset: -4px`，保留旧 `outline-offset: 2px` 的留白），焦点时 `opacity 0→1 + scale(0.97→1)` 平滑扩散 |
| `src/assets/styles/controls.scss` | 文本域因 `textarea` 不渲染伪元素，改用双层 `box-shadow`（0 扩散 → 2px）实现同款动画，并补回 `is-error` 红边状态                                    |
| `src/assets/styles/controls.scss` | 不再覆盖 EP 的 `hover` / `is-error` / `disabled` box-shadow，避免 ID 选择器权重压掉校验红边                                                        |

# 系主任 / 院长账号无法从管理端登录修复

- **日期**：2026-11-12
- **修改人**：ry
- **本次需求**：教师账号 `D2024105`（李国强，系主任）在「管理员登录」页签提示不是管理端账号，改用「学生登录」后接口返回 403「没有权限」。
- **根因**：
  - 该账号的角色码为 `department_head`（系主任，role level=4），后端判定 `student` 以角色 level=1 为准，因此后端认为它是管理端账号；
  - 前端 `TEACHER_SIDE_ROLE_CODES` 仍只列 `admin / teacher / counselor`，未包含多级审批流新增的 `department_head`（系主任）与 `college_dean`（院长），登录成功后在前端兜底校验里被误判，提示「该账号不是管理端账号，请改用学生登录」；
  - 改走学生页签时后端按 `loginType=student` 校验角色，返回 403「该账号不是学生账号，请改用管理入口登录」，即截图中的 403。
  - 补查发现 `department_head` / `college_dean` 在 `role_permissions` 中授权记录为 0，即使放行登录也会因权限码为空、且无角色基线菜单，导致教师端侧栏空白。
- **改动范围**：前端登录入口角色白名单与授权数据缺失时的角色基线菜单；后端登录校验逻辑未改动。
