## 二、新增/修改记录

### 2.1 注销接口 401 不再触发令牌刷新（修复「账号被删后无法退出登录」）

- **涉及文件**：`src/shared/api/request.ts`（修改）
- **修改内容**：
  1. `isBusiness401` 增加 `/auth/logout`：注销接口返回 401（账号已在后端被删除）时跳过令牌刷新链路；
  2. 响应拦截器 switch 的 401 分支新增 `/auth/logout` 判断，直接 `forceLogout()` 整页跳回登录页。
- **修改原因**：原逻辑下，账号被删后 `POST /auth/logout` 返回 401 → 触发 `tryRefreshToken`（后端 /auth/refresh 仅校验 JWT 签名、不校验账号存在性，刷新成功）→ 带新 token 重试 logout → 仍 401 → 再刷新……无限循环，`await apiLogout()` 永不返回，本地 token 永不清理，表现为「退不出登录」。

### 2.2 401 刷新重试上限（3 次）

- **涉及文件**：`src/shared/api/request.ts`（修改）
- **修改内容**：刷新分支条件增加 `((error.config as any).refreshCount || 0) < 3`；重试前对请求自身的 `config.refreshCount` 自增（挂在每个请求自己的 config 上，各请求独立计数、并发互不影响）。任何接口最多「刷新 + 重试」3 轮，第 4 次 401 不再进入刷新分支、落入 `forceLogout()`，杜绝刷新链路死循环（后端 /auth/refresh 未校验账号存在性时的前端兜底）。

### 2.3 审核记录 fetchByType 按 type 去重

- **涉及文件**：`src/app/stores/review.ts`（修改）
- **修改内容**：新增 `pendingByType: Map<string, Promise<ReviewRecord[]>>`，同一 type 并发调用共享同一 Promise（不同 type 互不阻塞）；请求体包进 IIFE 后存入 Map，`await` 完成后写入 `typeRecords` 并从 Map 清理。为 2026-08-31 全局去重治理的遗漏补全。

### 2.4 仓库 Vite 代理地址对齐

- **说明**：本机生效配置为 `vite.config.js`（已列入 .gitignore、不进仓库），其 target 已指向 8089；本次将随仓库分发的 `vite.config.ts` 同步为一致，保证其他环境克隆后代理可用。
