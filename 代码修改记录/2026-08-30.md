## 二、需求一：消除草稿自动保存 409「数据校验失败」弹窗

### 2.1 根因定位

1. **报错来自草稿自动保存，不是提交按钮**：`submission.ts:617` 位于 `createDraft()` 内的 `request.post(contract.endpoint, payload)`。触发链为 `useFormDraft` 的深 `watch(form)` → 800ms 防抖 → `saveToBackend()`；新记录无后端草稿 id（`currentId()==null`）时走 `createDraft(applicationType, { ...form })` 用 `isDraft:1` 建草稿。
2. **后端拒绝**：`archive_competitions` 表 `competition_type`、`award_level` 为 **NOT NULL**（V5 迁移，见 2026-08-26 需求 2 排查）。用户只输入一个字的表单缺 `competitionType`/`awardLevel` → INSERT 违反 NOT NULL → `DataIntegrityViolationException` → 409 code 60005「数据校验失败」。
3. **前端全局弹错**：`request.ts` 响应拦截器对 409 走 `default` 分支，执行 `ElMessage.error(error.response.data?.message)`。`saveToBackend` 内部的 `.catch` 虽静默吞掉异常，但拦截器已先弹窗 → 用户**边输入边弹错**。
4. **与需求 2 的区别**：需求 2 只挡了提交按钮（`handleSubmit` 校验 `requiredFields`）；草稿自动保存路径从未接入必填校验，`buildContractPayload` 对空字段 `continue` 跳过，导致缺 NOT NULL 字段的载荷直达后端。

### 2.2 修改内容

**涉及文件**：`src/shared/composables/useFormDraft.ts`（**修改**）

**修改内容**：

1. 新增 `fieldEmpty(v)` 单字段判空函数（`undefined/null/''/空数组`），与 `useApplicationPage` 必填校验判定一致。
2. `useFormDraft` 新增可选参数 `minDraftFields?: string[]`：新建后端草稿（`isDraft=1`）前必须非空的字段 key。
3. `saveToBackend()` 在 `id == null`（无后端草稿 id）分支前增加门控：`minDraftFields?.some((k) => fieldEmpty(form[k]))` 成立则**跳过建草稿**直接返回。此时草稿仍由 `saveLocal()` 写入 localStorage 兜底（现有逻辑，未改动），必填字段填齐后下一次自动保存再建后端草稿。

**涉及文件**：`src/shared/composables/useApplicationPage.ts`（**修改**）

**修改内容**：调用 `useFormDraft` 时传入 `minDraftFields: requiredFields.map((f) => f.key)`，即复用需求 2 已配置的各类型页必填字段（15 页均经 `useApplicationPage` 接入，无需逐页改动）。

## 三、需求二：空白表单离开不弹「保存草稿」提示

### 3.1 根因定位

`useFormDraft` 的深 `watch(form)` 在表单任意字段变更时触发 `save()`，而 `save()` / `saveNow()` 原先**无条件**置 `hasDirtyData = true`。`saveLocal()`（`isNonEmpty` 校验）与 `saveToBackend()`（`isNonEmpty` 校验）均已对空表单提前 return，唯独脏数据标记没有判空。

触发链：保存草稿 / 提交 / 取消编辑 → `resetForm()` 执行 `Object.assign(form, emptyForm())` → 触发深 watcher → 800ms 防抖后 `save()` 将空表单标记为脏数据 → 用户点击其他页面时路由离开守卫误弹「未保存」提示。

### 3.2 修改内容

**涉及文件**：`src/shared/composables/useFormDraft.ts`（**修改**）

1. `save()`：`hasDirtyData = isNonEmpty(form)`，空白表单（含保存草稿/提交后重置）不再标记为脏数据。
2. `saveNow()`：同上，`hasDirtyData = isNonEmpty(form)`。
3. `onBeforeRouteLeave` 守卫：条件改为 `!hasDirtyData || !isNonEmpty(form)`，双重兜底——即使处于 800ms 防抖窗口（`resetForm` 刚触发 watcher、`hasDirtyData` 尚未回落），离开时表单为空白也直接放行不弹提示。

## 四、影响范围

- **全部 15 个申报/奖项类型页**：必填字段未填齐前不再向 `POST /applications/{type}` 发送不完整的 `isDraft:1` 建草稿请求，从源头消除 409「数据校验失败」弹窗；草稿仍本地保存，不影响「编辑记录」回填。

- **提交链路**：`handleSubmit` 必填校验（需求 2）不变，两者解耦：校验挡提交，门控挡建草稿。

## 七、遗留事项（后端反馈）

1. **Draft 建草稿仍依赖必填字段**：本轮以前端门控规避 409，但后端草稿创建（`isDraft=1`）与正式提交共用同一 NOT NULL 约束，无法保存"只填了名字"的中间草稿。建议后端对草稿写入放宽 NOT NULL 约束（或插入时对缺省字段给默认值），使草稿可任意状态保存、提交时再校验——否则"草稿可随时保存"的产品语义永远无法成立。
2. **DTO 参数校验**：必填字段缺失应返回 400 + 明确字段提示，而非 `DataIntegrityViolationException` 泛化的 409「数据校验失败」（沿用需求 2 建议）。
