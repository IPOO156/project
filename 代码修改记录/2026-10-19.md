# 需求一：退出登录 / 强制登出后用户级本地存储全量清理

## 〇、背景与排查结论

原登出链路只清了 `user_info_cache` / `user_avatar_cache` / `teacher_me` 三处，**其余用户级残留未清理**。本轮先对全仓 `localStorage` / `sessionStorage` 写入点做全量排查：

| 键名                                                                                                                                                    | 用途                                                             |            处理             | 理由                           |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | :-------------------------: | ------------------------------ |
| `token` / `refresh_token` / `remember_me`                                                                                                               | 令牌                                                             |   已有 `clearAuth()` 处理   | —                              |

# 需求二：退出登录重置全部用户级业务 store

## 〇、背景

`src/app/stores/user.ts` 的 `logout()` 此前只清 token 与本机缓存，**业务 store 的 state 与模块级请求缓存完全未重置**。换账号登录后 60 秒 TTL 窗口内，首页 / 档案 / 消息 / 申报等页面可能直接命中上一账号的缓存数据。

两个必须同时处理的点：

1. 各业务 store 均为 setup 写法 `defineStore('x', () => {...})`，**Pinia 的 `$reset()` 对其无效**，需自行实现 `reset()`；
2. 多数 store 在**模块作用域**持有 `pendingFetch`（并发去重）与 `lastFetchedAt`（配合 `CACHE_TTL_MS = 60_000` 防跨页冗余请求）——**只清 state 挡不住缓存命中**，必须同时复位这些模块级变量。

## 一、删除范围

### 1.1 `src/app/stores/user.ts` — `logout()` 内

| 删除内容                                                                                             | 说明                                                                           |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `import { useTabsStore } from './tabs'` 与 `logout()` 内 `useTabsStore().clearAll()` 的 try/catch 块 | 统一由 `sessionReset.ts` 承担，`logout()` 只保留一句 `resetUserScopedStores()` |
| 原「登出必须清空身份缓存」的两行手工清理与注释                                                       | 同上                                                                           |
| 冗余的 tab 清理托管逻辑                                                                              | 同上                                                                           |

## 二、新增范围

### 2.1 新增文件

| 文件                             | 内容                                                                                                                                                                                                                                                                                               |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/app/stores/sessionReset.ts` | `resetUserScopedStores()`：集中调用各用户级 store 的 `reset()`、`useTabsStore().clearAll()`（try/catch 保底：极端场景 store 未注册时静默降级）、`clearUserScopedStorage()`。**刻意不 import `./user`**（user.ts 反向 import 本模块，避免循环依赖）；各 store 用 `useXxxStore()` 在函数体内惰性获取 |

### 2.2 各 store 新增 `reset()` action

均实现为「**先复位模块级请求缓存变量，再清 state**」，并在 `return` 中导出：

| Store               | 复位的模块级变量                                                               | 清空的 state                                                                                            |
| ------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| `activity.ts`       | `pendingFetch`、`lastFetchedAt`                                                | `activities`、`filteredActivities`、`loading`                                                           |
| `archive.ts`        | `pendingFetch`、`pendingTimeline`、`lastArchiveFetchAt`、`lastTimelineFetchAt` | `interests`、`grades`、`awards`、`dimensions`、`timelineEvents`、`profileData`、`loading`、`loadFailed` |
| `award-review.ts`   | 无（该 store 无模块级请求缓存）                                                | `allRecords`、`loading`                                                                                 |
| `career-plan.ts`    | `pendingFetch`、`lastFetchedAt`                                                | `plans`、`loading`、`loadError`、`aiAnalysis`                                                           |
| `home.ts`           | `pendingFetch`、`lastFetchedAt`                                                | `data`、`loading`                                                                                       |
| `notification.ts`   | `pendingFetch`、`lastFullFetchAt`                                              | `notifications`、`filteredNotifications`、`loading`、`loadError`、`processedIds`                        |
| `review.ts`         | `pendingFetch`、`lastFullFetchAt`、`pendingByType`（按 type 去重的 Map）       | `allRecords`、`typeRecords`、`loading`                                                                  |
| `submission.ts`     | `pendingFetch`、`lastFetchedAt`                                                | `records`、`filteredRecords`、`loading`、`loadError`、`withdrawnIds`，并移除持久化的撤回标记            |
| `teacherMessage.ts` | 原已含 `reset()`，无需改动                                                     | —                                                                                                       |

> `theme.ts` 未加 `reset()`：主题为用户偏好（设备级），不属于账号级数据。

### 2.3 `src/app/stores/user.ts`

`logout()` 中 token / 身份清空后调用 `resetUserScopedStores()`，并保留 `useTeacherMe().clear()`（教师身份为模块级 `ref`，`clearUserScopedStorage()` 只清 localStorage，需显式清内存态）。

## 三、影响范围

- 登出后所有用户级 store 的 state、请求去重 Promise、TTL 时间戳全部归零；换账号登录不会命中上一账号缓存。
- `pendingByType` / `processedIds` 等集合类缓存一并清空，避免跨账号去重误判。
- 循环依赖：`user.ts → sessionReset.ts → archive.ts → user.ts` 为本方案引入的已知环，相关引用均发生在函数体内、运行时才取值，不触发 TDZ；已由 `vue-tsc` 与生产构建验证。

# 需求五（补充）：存储键常量收编补漏（`user_info_cache` 残留硬编码）

## 〇、背景

需求一抽出 `shared/constants/storageKeys.ts` 后，仍有 3 处直接写死 `'user_info_cache'` 字面量未替换：

- `src/app/router/routes.ts`：学生守卫（`to.meta.student`）与教师守卫（`to.meta.teacher`）各 1 处，用于读取 `loginType` 做端级分流；
- `src/app/stores/tabs.ts`：`restore()` 读取 `loginType` 过滤教师端学生首页标签。

值虽与常量一致、不影响运行，但属「抽了常量却漏改引用」的隐患——后续若调整 key 名称，这三处会静默失效。

## 一、删除范围

| 文件                       | 删除内容                                              |
| -------------------------- | ----------------------------------------------------- |
| `src/app/router/routes.ts` | 2 处 `localStorage.getItem('user_info_cache')` 字面量 |
| `src/app/stores/tabs.ts`   | 1 处 `localStorage.getItem('user_info_cache')` 字面量 |

## 二、新增范围

| 文件                       | 新增内容                                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------ |
| `src/app/router/routes.ts` | 新增 `import { USER_INFO_CACHE_KEY } from '@/shared/constants/storageKeys'`；两处 `getItem` 改引用常量 |
| `src/app/stores/tabs.ts`   | 同上，导入常量并替换字面量                                                                             |

## 三、影响范围

- 行为零变化（`USER_INFO_CACHE_KEY` 的值与原字面量一致，均为 `'user_info_cache'`）。
- 全仓 `'user_info_cache'` 字面量仅剩 `storageKeys.ts` 中的唯一定义处，实现真正单点维护。
