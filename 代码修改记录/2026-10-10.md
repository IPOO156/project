## 零、定责结论（改代码前先定位，避免改错责任方）

**属前端。** 后端两处判据都是明确的、自洽的，不存在缺陷：

| 问题                                     | 结论                                       | 代码证据                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理员端有没有「授予学校级授权」的入口？ | **没有**（唯一来源是迁移自动播种给 admin） | 写接口 `PUT /admin/users/{userId}/scopes` 的校验 `UserManageService.validateScope`（`UserManageService.java:600-616`）用 `switch` 只放行 2/3/4，`default -> throw PARAM_ERROR`「scopeType 只能为 2(学院)/3(专业)/4(班级)」；前端数据范围配置页 `RoleAdjust.vue:158-160` 也只提交 `scopeType: 2/3/4`（选项来源 `:126-128` 同样按 2/3/4 过滤），`RoleAdd.vue` 只分配所属学院（2）。全仓 `scope_type=1` 的唯一写入口是迁移 `V35__ensure_role_permissions_and_scopes.sql:162-165`，`SELECT u.school_id, u.id, r.id, 1, u.school_id …` —— **按 admin 角色自动播种**，无接口/UI 可增删 |
| 「指定学期」为什么对教师必然 403？       | 后端口径如此且已实现                       | `AdminScoreService.triggerRecalculateByTeacher`（`:345-364`）→ `ensureSchoolScope(userId, schoolId)`（`TeacherScopeValidator.java:148-158`）只认 `scopeType=1 且 scopeId=schoolId`；教师 scopes 由迁移只播种到学院级（2），故恒不满足                                                                                                                                                                                                                                                                                                                                            |

**推论**：

1. 教师的「指定学期」**永久不可达** —— 不是「现在没授权」，是「没有任何途径能授权」。置灰 + 提示「需学校级授权」会误导用户去找管理员开通，而管理员开不了。
2. 但**不能整体删除**：`ensureSchoolScope` 对 admin 直通（`isAdmin` 短路），且前端只挂了 `/teacher/scores/recalculate` 一个重算页（`teacher-routes.ts:89`）、**无管理端等价页面**（全仓 `recalculate` 的 api 只有 `teacher.ts:326` 一处）。删掉即等于让管理员也无法从界面触发全校重算。

**因此对两个范围采用不同处理**（可申请 → 置灰；无入口 → 不展示）：

| 范围     | 判据                                                        | 处理                            | 理由                                                                          |
| -------- | ----------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------------------------- |
| 指定班级 | `canRecalcByClass`（admin / 校级 / **该班级**的班级级授权） | **置灰 + 提示「需班级级授权」** | 班级级授权**有**下发入口（角色管理→数据范围可授 `scopeType=4`），教师可去申请 |
| 指定学期 | `canRecalcBySemester`（admin / 校级）                       | **对非 admin 不展示**（不置灰） | 学校级授权**无任何下发入口**，留着只会误导                                    |

**「手动输入 ID」的取舍**：**保留输入能力，移除「手动输入」开关。**

- 内部主键（学生 `userId`、班级 `classId`）全仓**无一处展示**（grep `{{ …userId }}` / `classId` 命中 0 处），用户无从得知 —— 开关只服务于「猜 id」。
- 而猜中的小整数（1/2/3…）**可能恰好命中另一名学生**：后端 `ensureStudentInScope` 会通过（该生确在范围内），于是**不报错、静默算错人**。这不是功能，是危险入口。
- 「候选列表整体不可得」（接口失败 / 本人无授权班级）时的**自动兜底输入照旧保留**（`targetOptionsFailed` → 落手输），用户仍有路可走，不构成「影响用户使用」。

  4. 冷却 150s 后**单独跑该用例 → passed (6.7s)**。
