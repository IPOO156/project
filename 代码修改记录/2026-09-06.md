## 四、Bug 检查与修复记录（诊断通过，前端已修）

对照后端源码逐字段核验四个接口族 DTO（PendingListItem / PendingDetailResponse / HistoryItem / LogItem / MessageListItem / Org* DTO / 枚举 AuditActionEnum），前端字段名与后端一致。逻辑层发现并修复 4 处：

1. **铃铛角标被分类范围覆盖**（teacherMessage Store）：消息中心选定某分类后，接口 `unread` 是「该分类范围内」未读数，原逻辑会用它覆盖全局角标。修复：仅在全部分类 + 收件箱视图下才覆盖 `unreadCount`。

3. **批量通过部分失败无提示**（AuditPendingList）：原只提示成功条数。修复：`failed > 0` 时改为 warning 提示成功 / 失败分别条数。
4. **组织架构空态误显分页器**（OrganizationManagement）：未选组织 / 无班级时仍渲染 total=0 分页条。修复：`classTotal > 0` 才渲染。

## 五、后端缺口与说明清单（前端已用现有能力兜底，未改后端）

1. **教师消息无「取消归档」**：后端仅有 `PUT /teacher/messages/{id}/archive`，学生端 `/messages/{id}/unarchive` 未对教师开放。已归档消息无法回到收件箱（仅可查看）。如需恢复，需后端补充 `/teacher/messages/{id}/unarchive`。
2. **组织架构：学校 / 学院只读**：后端仅 `GET /admin/schools|colleges`，无创建 / 编辑接口。页面将其作为级联只读维度，仅专业（`POST /admin/majors`）与班级（`POST/PUT /admin/classes`）可增改。若产品需维护学校 / 学院层级，需后端补充对应写接口。
3. **审核撤销（revoke）**：后端 `/teacher/audits/{taskId}/revoke` 在 HTTP 层即要求 admin 角色；审核记录列表当前按权限未暴露「撤销」入口（正常教师无权限，属预期）。若需在 UI 显式提供该操作按钮，需后端放宽或前端按角色显隐（本轮未做，避免越权入口）。
4. **审核详情无 submitTime 字段**：详情 DTO（PendingDetailResponse）不含提交时间，仅审批历史 `createdAt`。页面以「审批步数 + 申请人 / 学期摘要」呈现，未伪造提交时间。
5. **审核历史非空字段可为 null**：HistoryItem 的 archiveType / title / studentName / studentNo / actionLabel / comment 在特定动作（如撤回）下可为 null，前端已全部做空值 `-` 兜底。

## 二、新增/修改记录（本次新增范围）

1. **`src/shared/api/request.ts`——新增匿名 401 分流与 reload 循环守卫**
   - 新增 `isBusiness401(url)`：`/auth/login`、`/auth/password` 的 401 视为「凭据/验证码有误」，仅提示错误，不走刷新与登出（否则原密码输错会误登出）。

   - 原「401 → 刷新重试 → 成功原样重试 / 失败登出」的主链路保留不变（带令牌的会话过期仍正确走刷新）。

2. **`src/shared/api/teacher.ts`——导出模板返回类型更正 + 契约注释**
   - `getTeacherExportTemplates` 返回类型改为 `Promise<PageResult<TeacherExportTemplate>>`，并注释说明该接口与 `/teacher/exports/jobs` 同型返回分页包装、调用方须解包 `.list`（防止后续复用再次踩坑）。

3. **`src/features/teacher/archive-export/ArchiveExport.vue`——loadTemplates 解包 .list**
   - `templates.value = res.list ?? []`；`catch` 兜底置空。实测重载后 0 告警、下拉展示 3 个带 label 的模板选项。
