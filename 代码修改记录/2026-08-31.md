2. **前端现状**：`useSubmissionStore.withdrawRecord` 撤回成功后仅 `updateLocalStatus(id, 'withdrawn')` 改本地 status，**保留**了撤回前（待审批态）的 `canEdit/canDelete`（均为 false）；重拉列表后后端把记录当作草稿返回 `canEdit=true` → 操作列重新出现「编辑」。
3. **需求语义**：撤回 = 撤销本次申报。已撤回记录仅允许 查看/删除，不允许再次编辑（与 `ProofUpload.vue` 附件「withdrawn 允许删除」口径一致，见 `useApplicationStatus`/`ProofUpload`）。

### 2.2 `submission` Store：撤回记录记入 withdrawnIds，重拉保持「已撤回/不可编辑」

**涉及文件**：`src/app/stores/submission.ts`（**修改**）

**修改内容**：

1. 新增 `withdrawnIds` ref（`string[]`）并 **localStorage 持久化**（key=`submission:withdrawnIds`）：`withdrawRecord` 成功后把记录 id 记入集合并落库，`fetchRecords`/筛选重拉时据此强制保持「已撤回」态——覆盖**页面刷新**场景（会话内标记在刷新后会丢失，后端又返回草稿 can_edit=true，故必须持久化；见遗留事项后端根治方案）。
2. 新增 `applyWithdrawnMarks(list)`：对 `withdrawnIds` 中的记录强制置 `status='withdrawn'`、`canEdit=false`、`canDelete=true`，`fetchRecords` 的 records / filteredRecords 两条路径均应用。
3. `updateLocalStatus`：`newStatus === 'withdrawn'` 时一并写入 `canEdit=false、canDelete=true`，保证本地即时更新也符合「撤回后不可编辑」语义。
4. `deleteSubmission`：删除已撤回记录时同步从 `withdrawnIds` 清理该 id，避免遗留脏标记。

```ts
// withdrawRecord：撤回成功后记入 withdrawnIds 并持久化（后端撤回落库为草稿，重拉需本地补标记）
if (!withdrawnIds.value.includes(id)) {
  withdrawnIds.value.push(id)
  persistWithdrawnIds()
}
updateLocalStatus(id, 'withdrawn')

// updateLocalStatus：撤回态强制 不可编辑、可删除
const patch: Partial<SubmissionRecord> = { status: newStatus as any }
if (newStatus === 'withdrawn') {
  patch.canEdit = false
  patch.canDelete = true
}
```

### 2.3 报名记录操作列：withdrawn 显隐判断

**涉及文件**：`src/features/messages/activities/ActivityList.vue`（**修改**）

**修改内容**：`canEditSubmission`/`canDeleteSubmission` 增加 `withdrawn` 显式分支（后端开关未返回或重拉为草稿时也不被回退逻辑放行）：

```ts
function canEditSubmission(row: SubmissionRecord): boolean {
  if (row.status === 'withdrawn') return false // 撤回后不可编辑
  return row.canEdit !== undefined ? row.canEdit : row.status !== 'approved'
}
function canDeleteSubmission(row: SubmissionRecord): boolean {
  if (row.status === 'withdrawn') return true // 撤回后允许删除
  return row.canDelete !== undefined ? row.canDelete : row.status !== 'approved'
}
```

# 需求 10：科研之星提交后申报记录不显示修复（列表 archive_type 无子类型 → 按标题定位子页签）

- **需求来源**：「奖项报名中竞赛之星和双创提交成功之后都会有申报记录，但科研之星申报成功之后没有出现申报记录，什么原因」。
- **验证结果**：
  - `node node_modules/eslint/bin/eslint.js src/shared/composables/useFormRecords.ts --max-warnings 0` 通过
  - `node node_modules/vue-tsc/bin/vue-tsc.js -b` 通过

## 一、根因定位（前后端源码交叉确认）

1. **提交本身成功，数据未丢**：后端 `AwardService.submitResearchStar`（`AwardService.java:375-403`）创建 `award_applications` 主记录（status=PENDING，title=`科研之星-科研项目`/`科研之星-软件著作权`/`科研之星-发表论文`），子类型写 `award_research_stars.primary_category`（取值 `project`/`software_copyright`/`published_paper`）。
2. **列表项不暴露子类型**：`ActivityService.toListItem(AwardApplication)`（`ActivityService.java:299-315`）对三类星统一 `archiveType = a.getAwardType()` = `research_star`（`AwardTypeEnum.RESEARCH_STAR`），列表项仅有 title/archiveTypeLabel（`科研之星`），**无子类型字段**。
3. **科研之星页三个子页签过滤不到**：科研项目/软件著作权/发表论文三子页各自 `useApplicationPage` → `useFormRecords.loadRecords` 按 `accepted = {type, ...ARCHIVE_TYPE_ALIASES[type]}` 过滤：
   - 科研项目：`{'scientificProject','research_project','scientific_project'}`
   - 软件著作权：`{'softwareCopyright','software_copyright'}`
   - 发表论文：`{'paper','published_paper'}`
     `research_star` 三个集合都不匹配 → 主记录在三个子页全被滤掉 → 「没有申报记录」。
4. **对照**：竞赛之星 `archive_type='competition_star'`、双创 `archive_type='innovation_star'` 分别命中 `ARCHIVE_TYPE_ALIASES['competitionStar']`/`['innovationStar']`，故正常显示。
5. **消息中心「报名记录」tab 不受影响**：`getSubmissionRecords` 全量映射不过滤 archive_type，科研之星记录以 typeLabel=`科研之星` 正常展示（type 为原始 `research_star`）。

## 二、删除记录

无（本次无删除，仅新增/修改）。

## 七、遗留事项（后端反馈）

1. **后端根治（推荐）**：`ActivityService.toListItem(AwardApplication)` 对 `awardType=research_star` 的记录，按 `award_research_stars.primary_category`（`project`/`software_copyright`/`published_paper`）映射 archive_type：`project→research_project`（或 `scientific_project`）、`software_copyright→software_copyright`、`published_paper→published_paper`。落地后前端三个子页现有 aliases 集合全部命中、**无需任何前端改动**，前端 `RESEARCH_STAR_TITLE_HINTS` 分支自动失效（保留即可，无副作用）。
2. **连带修复**：子类型补全后，消息中心「报名记录」对科研之星记录的 查看/编辑 跳转（`sourcePathOf` 经 `ARCHIVE_TYPE_TO_KEY` 归一化为 scientificProject/softwareCopyright/paper → `/awards/scientific-star?sub=project|copyright|paper`）自动正确；当前 `research_star` 未归一化，`sourcePathOf` 会落到不存在的 `/applications?tab=research_star`。
3. **草稿主记录定位**：未提交（primary_category 为空）的科研之星主记录 title=`科研之星` 无子类后缀，前端标题定位无法归属到具体子页签（当前也不会显示）；由于前端科研之星流程只在最终提交时创建后端主记录（草稿仅本地持久化），实际无此场景，后端根治时可将空 primary_category 映射回 `research_star` 或默认子类型。
