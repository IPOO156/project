2. **前端现状**：`useSubmissionStore.withdrawRecord` 撤回成功后仅 `updateLocalStatus(id, 'withdrawn')` 改本地 status，**保留**了撤回前（待审批态）的 `canEdit/canDelete`（均为 false）；重拉列表后后端把记录当作草稿返回 `canEdit=true` → 操作列重新出现「编辑」。
3. **需求语义**：撤回 = 撤销本次申报。已撤回记录仅允许 查看/删除，不允许再次编辑（与 `ProofUpload.vue` 附件「withdrawn 允许删除」口径一致，见 `useApplicationStatus`/`ProofUpload`）。

### 2.2 `submission` Store：撤回记录记入 withdrawnIds，重拉保持「已撤回/不可编辑」

**涉及文件**：`src/app/stores/submission.ts`（**修改**）

**修改内容**：

1. 新增 `withdrawnIds` ref（`string[]`）并 **localStorage 持久化**（key=`submission:withdrawnIds`）：`withdrawRecord` 成功后把记录 id 记入集合并落库，`fetchRecords`/筛选重拉时据此强制保持「已撤回」态——覆盖**页面刷新**场景（会话内标记在刷新后会丢失，后端又返回草稿 can_edit=true，故必须持久化；见遗留事项后端根治方案）。
2. 新增 `applyWithdrawnMarks(list)`：对 `withdrawnIds` 中的记录强制置 `status='withdrawn'`、`canEdit=false`、`canDelete=true`，`fetchRecords` 的 records / filteredRecords 两条路径均应用。
3. `updateLocalStatus`：`newStatus === 'withdrawn'` 时一并写入 `canEdit=false、canDelete=true`，保证本地即时更新也符合「撤回后不可编辑」语义。
4. `deleteSubmission`：删除已撤回记录时同步从 `withdrawnIds` 清理该 id，避免遗留脏标记。

```ts
// withdrawRecord：撤回成功后记入 withdrawnIds 并持久化（后端撤回落库为草稿，重拉需本地补标记）
if (!withdrawnIds.value.includes(id)) {
  withdrawnIds.value.push(id)
  persistWithdrawnIds()
}
updateLocalStatus(id, 'withdrawn')

// updateLocalStatus：撤回态强制 不可编辑、可删除
const patch: Partial<SubmissionRecord> = { status: newStatus as any }
if (newStatus === 'withdrawn') {
  patch.canEdit = false
  patch.canDelete = true
}
```

### 2.3 报名记录操作列：withdrawn 显隐判断

**涉及文件**：`src/features/messages/activities/ActivityList.vue`（**修改**）

**修改内容**：`canEditSubmission`/`canDeleteSubmission` 增加 `withdrawn` 显式分支（后端开关未返回或重拉为草稿时也不被回退逻辑放行）：

```ts
function canEditSubmission(row: SubmissionRecord): boolean {
  if (row.status === 'withdrawn') return false // 撤回后不可编辑
  return row.canEdit !== undefined ? row.canEdit : row.status !== 'approved'
}
function canDeleteSubmission(row: SubmissionRecord): boolean {
  if (row.status === 'withdrawn') return true // 撤回后允许删除
  return row.canDelete !== undefined ? row.canDelete : row.status !== 'approved'
}
```

## 六、遗留事项（后端反馈 / 前端残留）

1. **后端可将撤回落库为 `已撤销`（REVOKED=4）**：当前后端撤回把记录置为 `status=0`（草稿），列表接口不返回 `revoked_at`，前端无法从接口区分「已撤回」与「普通草稿」，故本地持久化 `withdrawnIds`（localStorage，key=`submission:withdrawnIds`）跨刷新保持撤回标记。若要根治（撤持久化语义由服务端保证、多端一致），需后端在撤回时保留「已撤销」状态（REVOKED=4）或在列表 DTO 暴露 `revoked_at`，届时前端可移除本地标记。

# 需求 7：申报记录点「编辑」表单空白修复（详情 detail→表单字段逆向映射）

- **需求来源**：「申报记录里面点击编辑没有跳出原本已填写内容是空白的」——对真实申报记录点编辑，表单应回填已填内容，实际全为空白。
- **验证结果**：

## 一、根因定位

1. **后端详情结构**：`GET /activities/{type}/{activityId}` 返回 `ActivityDetailResponse`，业务字段**嵌在嵌套对象 `detail`**（`ActivityService.buildArchiveDetail` 生成的 `Map<String,Object>`），且用**后端字段名**（`obtainTime`/`competitionType`/`certificateNo`…）；学期在顶层返回 `semesterName`，附件在顶层返回 `evidenceFiles`（`file_id`/`file_name`/`file_url`）。
