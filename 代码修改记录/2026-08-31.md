# 代码修改记录

- **日期**：2026-08-31
- **修改人**：nine-mirrors
- **需求来源**：自测问题修复——① 退出登录时出现多余 401 与注销接口重复调用；② logout 异步化后退出不跳转登录页、需手动刷新；③ 页面切换时同一接口被重复请求，联调阶段后端压力大
- **验证结果**：vue-tsc -b 通过（exit 0）

## 一、删除记录

### 1.1 删除 logout 中 fire-and-forget 的滞后注销调用

- **涉及文件**：`src/app/stores/user.ts`
- **删除内容**：`apiLogout().catch(() => {})`
- **删除原因**：原逻辑在 `clearAuth()` 清空 token **之后**再次调用注销接口，请求不携带 Authorization，后端返回 401 并触发响应拦截器的令牌刷新链路（多余请求 + 无意义 401）。注销请求已提前至清 token 之前统一发出，该滞后调用删除。

### 1.2 删除 fetchRecords 的「全量 + 条件」双请求逻辑

- **涉及文件**：`src/app/stores/submission.ts`
- **删除内容**：`if (records.value.length === 0) records.value = await getSubmissionRecords()` 与 `filteredRecords.value = filters ? await getSubmissionRecords(filters) : records.value` 的组合写法
- **删除原因**：传 filters 时会先发一次全量请求、再发一次条件请求（两次 GET /activities）。重写为按场景只发一次：有 filters 只发条件请求；无 filters 只发全量并写入缓存。

## 二、新增/修改记录

### 2.1 退出登录顺序修正（先注销后清理）

- **涉及文件**：`src/app/stores/user.ts`（修改）
- **修改内容**：`logout()` 改为 async；先 `try { await apiLogout() } catch {}`（此时 token 仍有效，注销请求携带 Authorization），完成后依次清空内存 token / userInfo / cachedAvatar、`clearAuth()`、移除头像缓存、延迟获取 tabsStore 并 `clearAll()`。后端注销失败不阻塞本地登出。

### 2.2 退出登录调用方 async/await 化

- **涉及文件**：`src/app/layouts/components/HeaderBar.vue`、`src/app/layouts/components/Sidebar.vue`（修改）
- **修改内容**：`handleLogout`、`switchToStudent`（HeaderBar）与 `handleSwitchToStudent`（Sidebar）三个入口改为 `async function`，`await userStore.logout()` 完成后再 `router.push('/login')`。修复 logout 异步化后跳转先于本地状态清理执行、路由守卫仍能读到 token 导致「退出后不跳登录页」的问题。

### 2.3 Store 层接口去重（pending 并发拦截 + 60s TTL 缓存）

- **涉及文件**（均为修改）：
  - `src/app/stores/archive.ts`：`fetchArchive` / `fetchTimeline`（两组独立 pending 与时间戳）
  - `src/app/stores/home.ts`：`fetchDashboard`
  - `src/app/stores/activity.ts`：`fetchActivities`
  - `src/app/stores/career-plan.ts`：`fetchPlans`
  - `src/app/stores/notification.ts`：`fetchNotifications`
  - `src/app/stores/review.ts`：`fetchAll`
  - `src/app/stores/submission.ts`：`fetchRecords`（配合 1.2 重写）
- **修改内容**：统一去重模式：
  1. 并发拦截：`pendingFetch` 存在时直接 `return pendingFetch`，多个调用方共享同一飞行中请求，只发一次；
  2. TTL 缓存：数据非空且距上次成功拉取 < 60_000ms 时直接使用缓存不再请求（跨页面切换冗余去重）；
  3. 请求体包进 IIFE 赋给 `pendingFetch`，`finally` 中置空清理。
     带 filters 的条件查询不受 TTL 限制（用户筛选行为必须每次真实请求）。

### 2.4 登录页验证码请求去重

- **涉及文件**：`src/features/auth/Login.vue`（修改）
- **修改内容**：`loadBackendCaptcha` 增加 `captchaPending` 拦截——onMounted 首载、点击刷新、学生/管理员身份切换、登录失败重试 4 个触发点并发时，同一时刻只发一次 `POST /auth/captcha`，其余调用共享同一 Promise。
