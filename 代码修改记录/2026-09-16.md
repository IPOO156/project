## 四、下午审计修复（管理员端接口全量审计）

### 4.1 P0：审批委托菜单权限反转

**问题**：后端 `TeacherDelegationService` 明确写着"审批委托为教师专属"（L62），V35 迁移只给 teacher/counselor 授了 `delegate:manage`。但前端菜单权限挂了 `ADMIN_MENU_CODE` → admin 看到菜单 → 调 `/teacher/delegations` 被 Service 层 `requireAdminOrPermission(teacherId, "delegate:manage")` 拦截返回 20005。

**修复**：

| 文件                                         | 改动                                                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `src/shared/config/teacherModuleRegistry.ts` | `delegation` 模块 permissions 从 `[ADMIN_MENU_CODE]` 改为 `['delegate:manage']`；注释改为"审批委托为教师专属" |
| `src/app/router/teacher-routes.ts`           | 路由注释更新为"审批委托为教师专属"                                                                            |

**效果**：

- 管理员侧边栏不再出现"审批委托"菜单
- 教师/辅导员侧边栏正常显示该菜单（持 `delegate:manage` 权限码）
- 前后端口径对齐：后端 Service 层校验的权限码 = 前端菜单注册的权限码

**业务口径澄清**：

| 功能             | 谁发起             | 后端                                    | 前端                          |
| ---------------- | ------------------ | --------------------------------------- | ----------------------------- |
| 审批委托         | **教师**           | ✅ TeacherDelegationService             | ✅ 教师端可见（admin 已移除） |
| 管理员审核人分配 | **管理员定义规则** | ✅ ApprovalFlow + ApprovalNode 自动分配 | ✅ 审批流程配置模块已有       |

> 管理员不是临时手动批量指派审核人，而是在「审批流程配置」中定义规则（哪类申报 → 哪些角色 → 哪些范围），后端在提交时根据**规则 + 教师身上的授权**自动计算具体审核人。此功能已实现，见 `ApprovalNodeAssignTypeEnum.AutoAssign = 1`。
