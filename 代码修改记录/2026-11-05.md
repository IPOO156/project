# 首次登录强制改密前端处理（登录页内切换改密表单 + 403 兜底）

- **日期**：2026-11-05
- **本次需求**：新建账号使用初始密码登录后，后端要求先改密，否则除 `/auth/password`、`/auth/me`、`/auth/logout` 外的接口统一返回 403「首次登录请先修改初始密码」；前端此前把该 403 统一提示为「没有权限执行此操作」，且不跳转改密页。本次补齐强制改密流程，并确认影响范围。
- **改动范围**：仅前端。后端、数据库、接口路径/方法均未改动。

## 一、影响范围核查结论

| 项       | 结论                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 触发角色 | **所有角色**，不区分学生 / 教师 / 辅导员 / 管理员                                                                                                      |
| 触发时机 | ① 管理员新建账号（即使显式设密）；② 批量导入账号；③ 管理员重置密码后                                                                                   |
| 后端拦截 | `must_change_password=1` 时仅放行 `/auth/password`、`/auth/me`、`/auth/logout`，其余接口 HTTP 403 + code `20005` + message「首次登录请先修改初始密码」 |
| 标记下发 | 仅在登录响应 `user.mustChangePassword` 中返回；`/auth/me` 不返回该字段                                                                                 |
| 解除时机 | 用户自行改密成功（`PUT /auth/password`）或邮箱重置密码确认成功后置为 `false`                                                                           |

## 四、交互流程

1. 用初始密码登录 → 登录响应 `mustChangePassword=true` → 登录卡片原地切换为「请修改初始密码」表单，页面不跳转；登录密码仍在内存中，只填新密码与确认密码即可。
2. 刷新页面 → 本地标记仍在 → 登录页直接显示改密表单；内存中已无登录密码，此时补显「原密码」输入框用于身份校验。
3. 标记丢失（旧令牌、其他设备）→ 任意接口 403 → 提示后端原文并整页回登录页 → 由 403 写入的标记展示改密表单。
4. 改密成功 → 后端吊销全部令牌 → 前端清除标记、本地登出、换验证码，提示使用新密码重新登录。
5. 点「退出登录」→ 放弃本次登录，回到普通登录表单。
