## 〇、首要澄清：前端没有独立的「管理员端」

这是理解本报告的前提，也影响「三端是否都确认了」的判断。

| 事实                              | 证据                                                                                                                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/features/` 下无 `admin` 目录 | 实际目录仅有 `ai-chat / applications / approval / auth / awards / dashboard / growth-timeline / messages / profile / submission-records / teacher / teacher-shared` |
| 路由无 `/admin` 前缀              | `src/app/router/routes.ts` 只有 `/teacher` 前缀（L187）；`teacher-routes.ts` 亦同                                                                                   |
| 管理员登录后落在教师端首页        | `src/features/auth/Login.vue` 管理员分支跳转 `/teacher/dashboard`                                                                                                   |

**结论**：管理员与教师**共用同一套 `/teacher/*` 前端代码**，靠 `GET /auth/me` 返回的 `permissionCode` 控制菜单/路由可见性来区分身份。

因此：**教师端的前端覆盖 = 管理员端的前端覆盖**。接口比对是全局机械扫描（扫 `src/` 下全部调用，不按端切分），天然三端全覆盖；假数据扫描按「学生端模块 / 教师端模块（内含管理员端）」两路并行，覆盖的即是全部前端代码。

## 一、接口对接检测

### 1.1 方法

脚本 `extract.mjs`：

1. 遍历后端全部 `*Controller.java`，正则提取 `@GetMapping/@PostMapping/@PutMapping/@DeleteMapping/@PatchMapping`，拼接类级 `@RequestMapping` 前缀与 `/api/v1`。
2. 遍历前端 `src/**/*.{ts,vue}`，正则提取 `request.<method>(<path>)` / `axios.<method>(<path>)`。
3. 路径归一化：剥离 query、`${x}` → `{p}`、`{x}` → `{p}`、去尾部斜杠。
4. 双向 diff，并额外做**全量 HTTP 方法一致性扫描**（266 × 250 组合）。

1. **无「乱接接口」**：250 个后端端点、266 处前端调用，路径全部有对应，HTTP 方法零不一致。修复前的 3 处错误路径已移除。
