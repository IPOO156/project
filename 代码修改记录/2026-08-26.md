## 七、需求 2：竞赛申报提交 409 排查与必填校验补全

- **需求来源**：`POST /api/v1/applications/competition` 返回 409 Conflict，响应 `{"code":60005,"message":"数据校验失败，请检查提交内容"}`。
- **验证结果**：
  - `node node_modules/eslint/bin/eslint.js src/shared/composables/useApplicationPage.ts src/features/applications/competition/CompetitionList.vue --max-warnings 0` 通过
  - `node node_modules/vue-tsc/bin/vue-tsc.js -b` 通过

### 七.1 根因定位（已用 curl 复现 + 逐字段隔离验证）

1. **后端表结构**：`archive_competitions` 表 `competition_type`、`award_level` 均为 **NOT NULL**（V5 迁移）；`archives` 表无 user+type 唯一约束。
2. **前端提交链路**：`useApplicationPage.handleSubmit` → `checkDuplicateBeforeSubmit` → `doSubmit` → `submitApplication` → `buildContractPayload`。`buildContractPayload` 对空字段（`raw === ''`）直接 `continue` 不发送；`handleSubmit` 此前**无任何必填校验**，表单 `required` 仅视觉星号。
3. **后果**：竞赛类型/获奖等级留空提交 → payload 缺 `competitionType`/`awardLevel` → 后端 INSERT 违反 NOT NULL → `DataIntegrityViolationException` → 全局异常处理器映射为 **409** code 60005（`DB_UNIQUE_CONSTRAINT`）。
4. **验证**：
   - `{"competitionName":"x"}`（缺类型/等级）→ 409 60005（与用户线上请求 content-length=67 一致）
   - 补 `competitionType:"national",awardLevel:"first"` → **200 提交成功**（archiveId 126/127/128）
   - 中文名 / national 等枚举码均通过；此前 10003 为 Windows curl 中文编码假象，浏览器真实请求无此问题。
