## 一、核实结论（对完整接口清单 4.1–4.19）

### 1.1 个人奖项 CRUD 接口确实缺失

完整清单中与「个人奖项」相关的仅有：

| 出处        | 接口/字段                              | 性质                                                                                     |
| ----------- | -------------------------------------- | ---------------------------------------------------------------------------------------- |
| 4.1         | `GET /profile/info` → `personalAwards` | **只读类别汇总**（category/totalCount/maxLevel/latestTime，数据源 `award_summaries` 表） |
| 4.16 / 4.17 | 档案导出的 `awards` 栏目               | 导出内容，来自已审核通过的档案                                                           |

**没有任何 `POST / PUT / DELETE` 个人奖项接口。** 奖项由申报/奖项报名模块（7.x / 8.x）产生后聚合进 `personalAwards`，前端无写入口。与团队 8/23 对账文档（docs/api-reconciliation-student.md）「后端无奖项 CRUD 接口」一致。

### 1.2 多维度画像空白的判断

前端映射链路正确（`onMounted → fetchArchive → applyProfileInfo` 按 `dimensionName/score/targetScore` 映射 `dimensionProfile` 到 5 维度）。**空白说明当前账号真实 `GET /profile/info` 响应的 `dimensionProfile` 为空/null**——即 `portrait_evaluation_scores` 表无该生画像评分记录（文档 4.2 明确「无画像数据时不返回虚构占位值」）。属后端数据未生成，非前端缺陷，前端不编造。

## 二、删除记录

### 2.1 撤销上一轮错误接线（`/archive/awards`、`/archive/dimensions`）

**涉及文件**：`src/shared/api/archive.ts`、`src/app/stores/archive.ts`

**删除内容**：奖项四函数改接 `GET/POST/PUT/DELETE /archive/awards` 的改动、`loadArchiveAwardsAndDimensions()` 及其调用、`idCounter/nextId` 的移除。

**删除原因**：`/archive/awards`、`/archive/dimensions` 是**遗留死契约**（对账文档明确 `/archive/*` 为死代码 Mock）。已 `git checkout` 恢复 `src/shared/api/archive.ts` 至 HEAD 基线。

### 2.2 移除 archive store 的个人奖项 CRUD

**涉及文件**：`src/app/stores/archive.ts`（**删除**）

**删除内容**：`createAward` / `editAward` / `removeAward` 及 `apiAddAward` / `apiUpdateAward` / `apiDeleteAward` 导入，并从 return 导出中移除。

**删除原因**：方案一后端无奖项 CRUD 接口，手动增删改无法落库（新增后刷新消失），保留只会误导。`awards` ref 保留，供简历导出/成长时间轴/AI 对话等消费。

## 三、新增/修改记录（方案一：个人奖项只读展示）

### 3.1 AwardsPanel.vue 改为只读

**涉及文件**：`src/features/profile/components/AwardsPanel.vue`（**重写**）

**修改内容**：

- Props 改为 `Array<{ category, totalCount, maxLevel, latestTime }>`（`/profile/info.personalAwards` 类别汇总形状）。
- 移除「新增」按钮、编辑/删除操作列、新增/编辑弹窗、`ElMessageBox` 删除确认、`saveAward`/`openAddAward`/`openEditAward`/`deleteAward` 及 `useArchiveStore` 依赖。
- 卡片头部注释「申报审核通过后自动汇总」；每条展示：类别名 + 最高级别 tag + `共 N 项` + 最近获奖时间；空态用 `el-empty` 提示。

**原因**：奖项由申报审核产生，面板只读展示聚合数据，杜绝「新增后刷新消失」假象。

### 3.2 ProfileInfo.vue 数据源与获奖总数

**涉及文件**：`src/features/profile/ProfileInfo.vue`（**修改**）

**修改内容**：

- `awards` computed 替换为 `personalAwards`（读 `archiveStore.profileData?.personalAwards ?? []`）。
- 新增 `totalAwardCount` computed = 各类别 `totalCount` 之和（原 `awards.length` 是行数语义，改为聚合总数）。
- 模板：`AwardsPanel :awards="personalAwards"`；「获奖总数」统计卡改为 `{{ totalAwardCount }}`。

### 3.3 archive store 备注

**涉及文件**：`src/app/stores/archive.ts`（**修改**）

**修改内容**：`applyProfileInfo` 仍将 `personalAwards` 映射为 `awards`（供简历导出/成长时间轴/AI 对话消费，未改动）；奖项 CRUD 区替换为方案一注释说明。
