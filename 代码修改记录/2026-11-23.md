## 三、说明

- 契约以《学生端接口文档》9.4.1 为准：响应 `text/event-stream`，每个事件一行 `data:` + JSON；`start` / `delta` / `done` / `error` 四类事件。
- `done.messageId` 是消息反馈（9.9）与重新生成（9.5）的入参，流式过程中拿不到，必须在 `done` 后回填。
- 用户中断用 `AbortController`；后端在中断后**不会落库**这条助手消息，前端保留已收到的片段并标注「已停止生成」，刷新后该回复消失（文档 9.4.1 前端接入要点 5）。
- 前置校验错误（会话不存在/非本人/已禁用/内容为空）仍是 `ApiResult` JSON，前端先判断 `Content-Type` 再决定解析方式。
- 不新增任何 npm 依赖：解析器用原生 `fetch` + `TextDecoder`，未引入 EventSource（不支持 POST 与 Authorization）。
- **部署注意**：生产/测试反向代理需对 `/api/v1/ai/conversations/*/messages/stream` 关闭缓冲（Nginx `proxy_buffering off;`、`proxy_read_timeout` ≥ 120s），否则事件会被攒批下发，前端仍是「一次性出现」。
