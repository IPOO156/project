# 二、本次发现并修复的新缺陷：加载失败被渲染成真实 0 值

## 2.1 背景（问题复现）

复查中先遇到一次 `/profile/info` 请求失败（隧道刚恢复时的瞬时不可达），页面随即渲染为：

| 位置       | 渲染值                                             | 问题                                                                       |
| ---------- | -------------------------------------------------- | -------------------------------------------------------------------------- |
| 平均绩点   | **0.00**                                           | 学生读到「我的绩点是 0」——比「没加载出来」严重得多                         |
| 获奖总数   | **0**                                              | 与「确实没有获奖」无法区分                                                 |
| 课程总数   | **0**                                              | 同上                                                                       |
| 画像卡标题 | 「暂无评分」                                       | 尚可接受，但与「加载失败」未区分                                           |
| 画像卡空态 | 「暂无画像评分数据，**请联系管理员完成评分计算**」 | **归因错误**：真实原因是网络失败，重试即可；却把学生支使去找管理员（§3.4） |

根因：`archive.ts` 的 `fetchArchive` 在 `catch` 中调用 `fetchArchiveFallback()`，后者刻意清空 `grades` / `awards`（这是对的——不编造数据），但**没有留下「我是失败清空的」这一信息**，页面无从区分「后端没有数据」与「没拿到数据」，于是照常按 0 渲染。

**确定性复现**（非依赖偶发）：用 Playwright `page.route` 中断 `/api/v1/profile/info`（`route.abort('connectionreset')`），稳定复现上述全部表现。

| 删除内容                                                        | 说明                                                                      |
| --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `catch { await fetchArchiveFallback() }` 中**无状态标记**的写法 | 失败信息在 store 内被丢弃，页面只能看到被清空后的空数组，无法区分两种成因 |
