# 修复申报保存草稿时「本人角色」等扩展信息未落库

- **日期**：2026-11-11
- **修改人**：ry
- **本次需求**：申报页保存草稿后，后端数据库中「本人角色」字段没有值；提交路径正常，只有保存草稿丢扩展信息。
- **根因**：扩展信息（本人角色 / 证书编号 / 发证单位 / 取得时间 / 有效期）由 `useApplicationPage` 中的 `extendedForm` 独立维护，`doSubmit` 在提交前把它合并进请求体；但草稿路径 `saveNow` 只把主表单 `form` 交给 `useFormDraft`，`saveLocal` 与 `saveToBackend` 都只用 `{ ...form }`，`extendedForm` 从未并入本地快照与后端请求体，导致草稿记录中扩展字段为空。
- **改动范围**：仅前端草稿保存链路（`useFormDraft` / `useApplicationPage`）及对应单测；提交接口、后端与其它业务逻辑均未改动。

## 四、说明

| 事项     | 说明                                                                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 契约映射 | 扩展字段沿用既有映射：`role→participantRole`、`certNumber→certificateNo`、`issuingAuthority→issuingUnit`、`validityPeriod→validUntil`、`acquisitionDate→obtainTime`，与提交路径一致 |
| 空值处理 | 扩展字段为空时不计入请求体（与 `doSubmit` 的 `                                                                                                                                      |     | undefined` 行为一致），不会覆盖主表单已有值 |
| 编辑回填 | 本地草稿快照现在包含扩展字段，列表「编辑」时 `extendedForm` 可直接回填；后端记录仍走详情接口 `mapDetailToForm` 回填                                                                 |
| 自动保存 | 只修改扩展信息也会触发防抖保存；必填字段不齐时仍只写本地，填齐后建后端草稿时一次带上扩展信息                                                                                        |
| 历史草稿 | 修复前保存的后端草稿扩展字段为空，需在页面重新编辑并保存一次；本地快照无扩展字段属正常现象                                                                                          |
