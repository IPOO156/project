## 一、删除记录

### 1.1 移除 career-plan.ts 的 Mock 假成功回退

- **涉及文件**：`src/shared/api/career-plan.ts`（修改）
- **删除内容**：`submitCareerPlan` 的 `.catch()` 中对后端真实失败返回 `Promise.resolve(buildRecord(nextId()))` 的 Mock 回退逻辑。
- **删除原因**：后端失败时返回假记录导致组件层弹「规划已提交」成功提示，列表出现刷新即消失的假数据，直接误导用户（审查报告 P0 §4.4）。

### 1.2 移除奖项列表页重复的学期-日期联动校验代码

- **涉及文件**：
  - `src/features/awards/competition-star/CompetitionStarList.vue`
  - `src/features/awards/innovation-star/InnovationStarList.vue`
  - `src/features/awards/scientific-star/PaperList.vue`
  - `src/features/awards/scientific-star/SoftwareCopyrightList.vue`
- **删除内容**：各页面中重复的 `buildSemesterMonthDisabledDate`、`isMonthInSemester`、`sanitizeSemesterMonthPair` 导入与调用、`handleSubmit` 包装函数、`disabledDate` computed。
- **删除原因**：4 个页面复制粘贴同一套校验逻辑，已下沉至 `useApplicationPage` 统一处理（见 §2.6），消除重复代码。

### 1.3 移除组件/组合函数层冗余错误提示

- **涉及文件**：`useApplicationPage.ts`、`useCorrection.ts`、`InterestPanel.vue`、`SelfEvaluationPanel.vue`
- **删除内容**：catch 块中的 `ElMessage.error('提交失败')` / `ElMessage.error('保存失败')` / `ElMessage.error('保存失败，请稍后重试')`。
- **删除原因**：所调用 API 透传 `request` 实例，失败时拦截器已弹出后端 message，组件再弹一条形成双重提示（审查报告 P1 §5.1）。

## 二、新增/修改记录

### 2.1 P0 假成功修复——个人信息保存失败不再弹「已保存」

- **涉及文件**：`src/features/profile/ProfileInfo.vue`（修改）
- **修改内容**：`saveEdit()` 的 catch 块中删除 `ElMessage.error('学籍信息保存失败')` 并立即 `return`，终止后续 `isEditing.value = false`、`fetchArchive()` 与 `ElMessage.success('已保存')`。
- **修改原因**：原逻辑下接口失败进入 catch 弹错后未 return，继续关闭编辑框并弹成功提示，用户看到「失败+成功」两条 toast 且编辑框关闭、但数据未保存（审查报告 P0 §4.1）。

### 2.2 P0 假成功修复——审核记录重新提交失败不再伪造 pending 状态

- **涉及文件**：`src/app/stores/review.ts`、`src/app/stores/award-review.ts`（修改）
- **修改内容**：`resubmit()` 移除 `try/catch` 吞错，改为直接 `await updateActivity(...)`，失败时错误向上抛出；删除本地状态伪造为 `pending` 的逻辑与 `ElMessage.success('修改已保存，等待重新审核')`。
- **修改原因**：原逻辑 catch 吞掉接口失败后无条件将本地状态置为 `pending` 并弹成功提示，刷新后状态复原为「已退回」，前端展示与后端实际状态不一致（审查报告 P0 §4.2、§4.3）。

### 2.3 P1 查重接口失败增加降级提示

- **涉及文件**：`src/shared/composables/useApplicationPage.ts`（修改）
- **修改内容**：`checkDuplicateBeforeSubmit` 的 catch 块中新增 `ElMessage.warning('查重服务暂不可用，本次未执行重复检测')`，保留放行策略（避免查重故障阻塞业务）。
- **修改原因**：原逻辑 catch 直接 `return true` 静默放行，用户无感知（审查报告 P1 §5.2）。

### 2.4 P2 全局错误兜底

- **涉及文件**：`src/main.ts`（修改）
- **修改内容**：
  1. 新增 `app.config.errorHandler`：捕获组件渲染错误，`console.error('[GlobalError]', err)` 并 `ElMessage.error('页面出现异常，请刷新重试')`；
  2. 新增 `window.addEventListener('unhandledrejection', ...)`：仅记录日志，不弹 toast（请求层 rejection 已由拦截器提示，避免重复弹窗）。
- **修改原因**：补齐 CLAUDE.md 3.4「前后端均需对异常进行日志记录和监控告警」要求，原项目无任何全局错误兜底（审查报告 P2 §5.4）。

### 2.5 P2 密码一致性校验提示级别与文案统一

- **涉及文件**：`src/features/auth/Login.vue`、`src/features/profile/EditPassword.vue`、`src/features/teacher/role-selection/RoleAdd.vue`（修改）
- **修改内容**：
  1. 三处「两次密码不一致」文案统一为「两次输入的密码不一致」；
  2. `EditPassword.vue`、`RoleAdd.vue` 由 `ElMessage.error` 改为 `ElMessage.warning`，与 `Login.vue` 及 `useApplicationPage` 必填校验一致。
- **修改原因**：表单本地校验失败属用户输入问题，统一用 warning 级别（审查报告 P2 §5.3）。

### 2.6 学期-日期联动校验逻辑下沉至 useApplicationPage

- **涉及文件**：`src/shared/composables/useApplicationPage.ts`（修改）
- **修改内容**：
  1. 新增 `semesterMonthConfig` 可选配置项（`{ monthField, monthFieldLabel }`）；
  2. 内部实现 `disabledDate` computed（基于 `buildSemesterMonthDisabledDate(form.semester)`）；
  3. `watch(form.semester)` 自动执行 `sanitizeSemesterMonthPair`；
  4. 提交前自动校验 `isMonthInSemester`，不匹配时 `ElMessage.error('${monthFieldLabel}与学期不匹配，请重新选择')`。
- **修改原因**：原 4 个奖项列表页各自实现同一套校验逻辑，下沉后单一数据源、变更只改一处。

### 2.7 登录页交互优化

- **涉及文件**：`src/features/auth/Login.vue`（修改）
- **修改内容**：
  1. 表单校验失败后自动聚焦对应输入框（用户名/密码/验证码/邮箱/新密码/确认密码）；
  2. 登录按钮添加 `native-type="submit"`，表单 `@submit.prevent="handleLogin"`，统一 Enter 键隐式提交链路；
  3. `handleLogin` 开头增加 `if (loading.value || loginSuccess.value) return` 防重复提交；
  4. 忘记密码多输入框表单添加隐藏 `<button type="submit">` 以触发 Enter 隐式提交（HTML 标准）。
- **修改原因**：提升表单可用性，Enter 键提交与点击提交走同一链路，避免校验提示后用户需手动点击输入框。
